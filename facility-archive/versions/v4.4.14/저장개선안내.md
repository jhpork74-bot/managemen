# v4.4.9 시트 저장 안정화

원본 저장 완료를 보고용 시트·캘린더 갱신과 분리했습니다. 저장이 끝나면 원본 버전을 먼저 확인하고, 보고 시트는 뒤에서 묶어 갱신합니다. 일부 보고가 늦어져도 원본이 미저장인 것처럼 표시하지 않습니다.

- 끊긴 응답 재시도는 같은 요청 번호를 사용하여 중복 저장을 방지합니다.
- 일시적인 연결·잠금 실패는 최대 3회 자동 재시도합니다. 버전 충돌은 자동 덮어쓰기 없이 멈추고 임시본을 유지합니다.
- 오프라인 변경은 기기에 보관하고 연결이 돌아오면 재시도합니다. 브라우저 저장소 차단·기기 저장공간 부족은 별도 오류로 안내합니다.
- JSON 조각 쓰기를 묶고 동일 내용은 새 버전을 만들지 않습니다. 비활성 슬롯 기록·검증 후 원본 포인터를 확정하는 기존 보호 장치는 유지합니다.
- 캘린더 API 처리 중에는 원본 저장 잠금을 유지하지 않습니다. 자동 동기화 호출도 묶습니다.
- 앱이 열린 동안 원본 저장 뒤 약 3초 후 보고 갱신을 요청합니다. 실패하거나 다른 작업이 진행 중이면 제한적으로 다시 시도하고 수동 재시도 버튼을 제공합니다.

## 설치

v4.4.7 이상 전용 파일 구성을 기준으로 Index.html, FacilityStorage.gs, CalendarReminders.gs를 교체하고 새 버전으로 배포합니다. Code.gs와 기존 연결 ID는 유지합니다. HTML은 Index에, .gs는 같은 이름의 스크립트에 넣습니다. 기존 전체 JSON·코드를 먼저 백업하세요.

앱을 닫아도 보고 시트를 갱신하려면 클라우드 상태의 **앱을 닫아도 보고 시트 자동갱신** 버튼을 한 번 누릅니다. 또는 Apps Script에서 **installFacilityStorageMaintenance**를 한 번 실행해 권한을 승인합니다. 약 5분 간격으로 보고 갱신 필요 여부를 확인하는 트리거를 중복 없이 설치합니다. 이 설정 전에는 앱을 닫으면 보고 시트 갱신이 다음 접속까지 늦어질 수 있습니다. 원본 저장 결과와는 별개입니다.

## 확인 범위

Node 모의 시험에서 원본 ACK 전 보고 I/O 없음, 같은 요청 재전송·동일 내용 중복 방지, 충돌·실패 슬롯 보호, 원본 확정 뒤 보조 속성 기록 실패, 보고/캘린더 작업 중 잠금 해제와 최신 보고 반영을 확인했습니다. 로컬 브라우저에서 응답 유실 뒤 재시도, 재시도 중 추가 변경 순서 유지, 보고 실패와 원본 성공 구분, 오프라인·재접속, 충돌 시 임시본 유지를 확인했습니다.

실제 운영 시트의 저장 속도를 측정하거나 운영 배포·실제 Google 알림을 실행하지 않았습니다. 인터넷·Google 서비스 오류를 모두 제거한다고 보장하지 않으며, 재시도 한도를 넘으면 임시본과 오류 안내를 남깁니다. 이메일 발송 기능은 추가하지 않았습니다.
