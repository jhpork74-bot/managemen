# v4.4.30 재물관리등록 전체통합 설치 안내

## 이번 다운로드의 범위

재물관리 신규등록·수정, 장소 등록, 회사 Drive 제품사진, 사진 아래 등록/변경, 최초장소/이동일/마지막장소 및 이동 이력, 연간 조사, 불용예정/완료, 담당자 개별 입력·일괄지정, 예시복지관 기본 기관명, 폼텍7종/직접 설정·위치 보정·라벨 출력, 일일 일반업무 초안 기준을 모두 포함합니다. 기존 당직·당직변경·잔디 수동 전송·고장공사·CSFS·저장 충돌 복구도 유지합니다.

메뉴는 이제 Index의 기본 HTML에 들어갑니다. 재물관리 모듈이 실행되지 않으면 메뉴를 누를 때 설치 확인 안내가 나옵니다. 모듈 초기화 오류도 해당 화면에 표시합니다. 운영 웹앱의 미표시 원인은 현재 배포 소스를 직접 받지 못해 확정하지 않았습니다. 이번 다운로드에는 부분 교체본뿐 아니라 일관된 전체 소스를 담았습니다.

## 1. 먼저 보관

현재 업무의 저장 완료를 확인하고 전체 JSON 백업을 내려받으세요. 기존 Apps Script 소스와 스크립트 속성을 보관하세요. 특히 기존 INI.gs의 INI_LEGACY_SPREADSHEET_ID와 사진 서명키 REPAIR_PHOTO_SIGNING_KEY를 유지해야 합니다. JSON에는 Drive 사진 파일/권한/서명키가 들어 있지 않습니다.

새 Apps Script 프로젝트나 새 스프레드시트를 만들지 않습니다. 기존 웹앱이 사용하는 같은 프로젝트에서 교체합니다. 기존 시트·사진·속성을 삭제하지 않습니다.

## 2. 파일 적용 — 메뉴가 계속 안 보이는 현재 상황

ZIP을 풀고 **1_전체소스_설치용**을 여세요. HTML8개와 스크립트16개가 모두 들어 있습니다. 기존 프로젝트에 같은 이름이 있으면 내용을 전체 교체하고, 없는 파일은 추가합니다. 다른 이름으로 복제하여 같은 함수가 두 개 생기게 하지 마세요. 사용자 개인 추가 파일은 임의로 지우지 않습니다.

**HTML 파일 8개**는 왼쪽 파일 옆 ＋ → HTML로 만듭니다. 이름에 .html을 중복 입력하지 마세요.

- Index
- DutyManagementUI
- DutyChangesUI
- RepairsManagementUI
- JandiNotificationsUI
- PopupBehaviorUI
- CSFSManagementUI
- AssetManagementUI

**GS 파일 16개**는 ＋ → 스크립트로 만듭니다. HTML을 스크립트에 붙여 넣으면 Unexpected token < 오류가 발생합니다.

- Code
- FacilityStorage
- DutyRosterCore
- DutyManagement
- DutyChanges
- RepairsManagement
- JandiNotifications
- JandiCalendarImages
- CalendarReminders
- NoEndRepeats
- PopupBehavior
- INI
- ConnectionSettings
- RepairPhotoStorage
- CSFSManagement
- AssetManagement

INI를 교체할 때 기존 INI_LEGACY_SPREADSHEET_ID는 본인이 사용하던 값으로 유지합니다. 내려받은 기본값이 현재 값과 다르면 기존 값을 옮깁니다. 회사 Drive 폴더 ID를 업무 스프레드시트 ID 자리에 넣지 않습니다. 기존 스크립트 속성과 웹훅·관리자·트리거는 삭제하거나 재초기화하지 마세요. applyIniSettings를 실행할 필요가 없습니다.

**부분 교체를 원하면:** 2_재물관리관련_누적9개 폴더는 v4.4.23 이후 재물관리 관련 변경을 한 번에 담은 세트입니다. 이번에는 HTML2개/GS1개만 있는 과거 패치 대신 누적9개 또는 위 전체24개 중 한 방법을 적용하세요.

## 3. 저장과 새 버전 배포

1. 모든 파일을 저장하고 구문 오류가 없는지 확인합니다. AssetManagement의 ||= 오류 수정도 포함했습니다.
2. 오른쪽 위 배포 → 배포 관리를 누릅니다.
3. 현재 사용하는 웹앱 배포를 선택하고 연필을 누릅니다.
4. **버전**을 **새 버전**으로 바꿉니다. 설명에 v4.4.30 재물관리 전체통합을 입력합니다.
5. 실행 계정과 접근 범위는 기존 설정을 유지하고 배포합니다.
6. 저장 버튼만 누르면 기존 /exec 웹앱은 바뀌지 않습니다. 반드시 위 새 버전 배포를 마치세요.
7. 기존 웹앱 창을 닫고 같은 배포 관리 화면에 있는 웹앱 /exec 주소를 복사해 다시 엽니다. 예전 배포의 다른 주소를 열지 않도록 확인합니다.

## 4. 설치 확인

- 화면 맨 아래 **v4.4.30 · 재물관리 전체통합**을 확인합니다. 다른 버전이면 현재 연 주소가 아직 이 수정본 배포를 사용하지 않는 것입니다.
- CSFS 바로 뒤에 **재물관리등록** 메뉴가 있는지 확인합니다.
- 메뉴를 눌러 신규등록/장소등록/담당자 일괄지정/라벨지출력 버튼이 있는지 봅니다.
- 모듈 파일 실행 안내나 초기화 오류가 나오면 그 문구를 그대로 전달하면 원인 확인에 도움이 됩니다. 다시 파일을 임의로 지우지 마세요.

## 5. 사진과 담당자·라벨

사진 연결이 이미 설정되어 있으면 다시 적용할 필요가 없습니다. 아직이면 기존 개인 관리자 편집기에서 setupFacilityConnectionSettings를 실행해 연결설정 시트의 재물조사 사진 저장 폴더(ASSET_IMAGE_FOLDER_ID) 행을 추가합니다. C열에 회사 재물조사 폴더 ID를 넣고 previewFacilityConnectionSettings로 변경 항목을 확인한 다음 applyFacilityConnectionSettings를 실행합니다. 기존 실행 계정에 회사 폴더 편집 권한이 필요합니다. 기존 사진을 이동/삭제하지 않습니다.

체크박스 선택 → 담당자 일괄지정 → 이름 입력 → 저장 완료 → 선택 유지 → 라벨지출력 순서로 씁니다. 기존 담당자가 있으면 새 이름으로 변경됩니다. 라벨은 담당자 표시 기본 체크이며 미지정 물품은 미입력으로 표시합니다. 개별 변경도 가능합니다.

폼텍 제품은 아직 확정하지 않았으므로 제품 미정/직접 설정으로 시작합니다. 실제 제품을 선택하고 일반 종이에 배율100%/머리글바닥글끔으로 시험 출력하세요. 여백·간격은 초기값이며 칼선 정렬/실물 프린터는 미검증입니다. 기관명·규격은 양식 설정 저장을 눌러 보관합니다.

## 검증·제한

로컬 모의 웹앱에서 메뉴 표시·열기·담당자/라벨 버튼·제품사진을 확인했습니다. 모듈 누락·초기화 실패 안내, GS 논리 대입 제거, 기존 재물·사진·담당자·라벨 보호 로직의 모의 검증을 통과했습니다. 실제 Google 운영 배포와 실물 인쇄는 직접 확인하지 않았습니다. 코드 복원으로 속성·권한·트리거·Drive 파일까지 복원되는 것은 아닙니다. GitHub 미게시 로컬 다운로드본입니다.
