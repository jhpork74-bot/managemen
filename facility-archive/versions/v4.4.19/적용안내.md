# v4.4.19 개인·회사 계정 함께 등록

JANDI_ADMIN_EMAIL을 실행할 때마다 바꾸는 대신 **개인 이메일과 회사 이메일을 쉼표로 한 번에 등록**합니다. 두 계정 중 어느 것으로 Apps Script 관리 함수를 실행하든 허용 목록을 확인합니다. 기존 한 계정 설정도 그대로 지원합니다.

회사 Drive 사진 저장 위치·업무 데이터·사진 확인키·잔디 웹훅·시험/토픽 모드는 유지합니다. 새 계정 자동 추가, 익명 사용자의 배포 소유자 권한 대체, 자동 메시지 발송은 하지 않습니다.

## 1. 파일 교체 — v4.4.18 기준

현재 운영 중인 같은 Apps Script 프로젝트를 사용합니다. 먼저 기존 소스·업무 JSON·스크립트 속성을 보관합니다.

`교체할_스크립트_GS3개`의 다음 파일 내용을 각각 기존 같은 이름 파일에 전체 교체합니다.

| 파일 | 작업 |
|---|---|
| INI.gs | 기존 INI_LEGACY_SPREADSHEET_ID를 메모하고 새 파일에도 같은 운영 시트 ID 유지 |
| ConnectionSettings.gs | 기존 내용 교체 |
| JandiNotifications.gs | 기존 내용 교체 |

**HTML 교체 없음. 새 스크립트 파일 추가 없음.** 제공한 전체복구용 폴더는 참고용이며 일괄 교체하지 않습니다. 기존 사진·폴더 ID·웹훅·REPAIR_PHOTO_SIGNING_KEY를 지우지 않습니다.

## 2. 관리자 이메일 두 개 등록 — 처음 한 번

1. Apps Script 왼쪽 톱니바퀴 **프로젝트 설정**을 엽니다.
2. **스크립트 속성**에서 `JANDI_ADMIN_EMAIL`을 찾습니다.
3. 값에 **실제 개인 Google 이메일, 실제 회사 Google 이메일**을 함께 입력합니다.

형식 예시이며 그대로 사용하지 마세요.

```text
personal@example.com, company@example.com
```

작은따옴표·큰따옴표 없이 이메일 사이에 **쉼표**만 넣습니다. 계정 비밀번호는 넣지 않습니다. 저장합니다. 관리자로 허용할 본인의 실제 두 계정만 기재합니다. 입력한 계정에 실제 프로젝트·운영 시트·회사 사진 폴더의 필요한 권한이 있어야 합니다.

이 설정은 같은 프로젝트 안에서 공유됩니다. 개인 계정용/회사 계정용으로 별도 프로젝트 두 개를 만들어 쓰는 경우에는 속성도 별개입니다. 이번 변경만으로 두 프로젝트가 자동 통합되거나 소유권·배포 권한이 이전되지는 않습니다.

## 3. 계정 확인

함수 목록에서 **checkFacilityAdminAccounts**를 실행합니다. 기존에 직접 추가한 AccountCheck의 단일 이메일 비교 함수는 복수 계정을 지원하지 않으므로 이 새 함수를 사용하세요.

정상적인 관리자 편집기 실행의 주요 결과는 다음과 같습니다.

```text
registeredAdmins: 2
currentAccountAllowed: true
sameExecutionAccount: true
settingsExecutionAllowed: true
```

이메일 실제값이나 비밀 주소는 로그에 출력하지 않습니다. 실행 계정이 다르거나 로그인 계정을 확인할 수 없으면 그대로 차단하며 자동으로 소유자 권한으로 대체하지 않습니다.

## 4. 연결설정 시트 갱신

**setupFacilityConnectionSettings**를 실행합니다. 시트의 관리자 항목에 복수 계정 안내가 표시됩니다.

이전 관리자 입력을 수정하지 않은 상태였다면 현재 등록한 두 계정 값을 C/D열에 함께 갱신합니다. C열에 별도로 작성 중인 변경값이 있으면 그대로 보존하므로, 관리자 행의 C열에도 개인·회사 이메일이 모두 들어 있는지 확인하세요.

나중에 시트에서 관리자 목록을 바꿀 때도 쉼표로 구분하고 **미리보기 → 적용**합니다. 적용 중인 본인 이메일이 목록에서 빠지면 실수로 접근을 잃지 않도록 중단합니다. 허용된 다른 관리자로 로그인한 뒤 본인을 포함하는 목록으로 변경할 수 있습니다.

## 5. 기존 배포 갱신

모든 파일 저장 → **배포 → 배포 관리 → 현재 배포 수정 → 새 버전 → 배포** 순서입니다. 기존 웹앱 탭을 닫고 다시 접속합니다.

앞으로 개인 계정에서 설정을 실행하든 회사 계정으로 배포하든 **JANDI_ADMIN_EMAIL을 번갈아 수정하지 않습니다.** 배포 실행 계정에 시트·폴더 접근 권한은 별도로 필요하며, Google 권한 동의나 트리거 소유자는 계정마다 다를 수 있습니다. 자동실행 트리거를 새 계정에 무작정 중복 설치하지 마세요.

## 6. 잔디 안내 문구 해석

사용자가 확인한 `이미 잔디 전송 성공을 확인한 변경입니다`는 서버가 같은 변경에 대해 잔디의 성공 응답을 기록했고 **중복 재발송을 하지 않았다는 뜻**입니다. 실제 수신방의 메시지/이미지 표시 여부를 보증하는 문구는 아닙니다.

현재 안내가 `개인 시험 대상 (나와의 대화)`라면 직원 전체 토픽이 아니라 개인 시험 Webhook 대상으로 설정되어 있습니다. 실제 Incoming Webhook이 연결된 방에서 기록 시각의 메시지를 확인하세요. 중복 방지를 풀거나 발송 기록을 삭제하지 않습니다. 실제 새 변경이 저장되면 새 이력으로 수동 전송할 수 있습니다. 시험을 위해 허위 업무 변경을 만들 필요는 없습니다.

읽기 전용 확인이 필요하면 **diagnoseJandiConnection**을 실행합니다. 설정 여부·개인/토픽 모드·사진 폴더 접근 여부만 출력하며, 메시지나 시험 사진을 생성·발송하지 않습니다. 폴더 쓰기/새 JPG 공개 공유/실제 잔디 수신은 이 진단으로 확인하지 않습니다.

로컬·모의 계정/Drive/Sheets/서버·Edge 회귀 검증이며 실제 두 Google 계정 실행·운영 배포·실제 잔디 이미지 수신은 확인 전입니다. 사용자는 v4.4.18 회사 Drive 사진 저장 정상 동작을 확인했습니다.
