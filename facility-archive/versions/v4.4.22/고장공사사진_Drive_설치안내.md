# v4.4.18 고장·공사 사진을 회사 Drive 폴더에 저장

앞으로 새로 등록하는 고장 사진과 공사 전·중·후 사진을 회사 Drive 폴더에 저장합니다. 업무 시트와 Apps Script는 기존 개인 계정에서 유지합니다. 스프레드시트·프로그램 전체를 회사 계정으로 복사할 필요는 없습니다.

로컬·모의 Drive/Google Sheets/서버·Edge 검증입니다. 실제 회사 폴더 생성·업로드·운영 배포·모바일 실기기는 아직 확인하지 않았습니다. 새 회사 폴더 ID를 직접 전달받지 않아 운영 연결은 아직 바꾸지 않았습니다.

## 1. 준비

1. 기존 웹앱의 전체 백업을 다운로드하고 기존 소스 및 스크립트 속성을 별도로 보관합니다.
2. 회사 계정에서 사진을 저장할 Drive 폴더를 엽니다. 공유 설정에서 기존 웹앱 실행 개인 계정에 **편집자** 권한을 줍니다. 메일을 보내지 않으려면 사용자 알림 체크를 해제합니다.
3. Apps Script는 기존 개인 관리자 계정으로 엽니다. **JANDI_ADMIN_EMAIL은 기존 개인 실행 계정**을 유지합니다. 회사 폴더를 사용한다는 이유로 회사 이메일로 바꾸지 않습니다.
4. 폴더 ID는 회사 이메일 주소가 아닙니다. `https://drive.google.com/drive/folders/폴더ID`의 폴더 ID 또는 전체 폴더 주소를 사용합니다.

## 2. 파일 설치 — v4.4.17 기준

새 프로젝트를 만들지 말고 기존 운영 프로젝트에서 진행합니다. 저장·잔디 전송이 진행 중이지 않을 때 설치하세요.

| 종류 | 파일 | 작업 |
|---|---|---|
| 스크립트 GS | INI.gs | 기존 내용 교체. 기존 INI_LEGACY_SPREADSHEET_ID를 먼저 메모하고 새 파일에서도 같은 값 유지 |
| 스크립트 GS | ConnectionSettings.gs | 기존 내용 교체 |
| 스크립트 GS | RepairPhotoStorage.gs | 새 스크립트 `RepairPhotoStorage` 생성 후 전체 내용 붙여넣기 |
| HTML | RepairsManagementUI.html | 기존 HTML `RepairsManagementUI`의 내용 교체 |
| HTML | PopupBehaviorUI.html | 기존 HTML `PopupBehaviorUI`의 내용 교체 |

HTML을 .gs 파일에 붙여넣지 마세요. Index.html과 Code.gs 및 나머지 모듈은 유지합니다. 포함된 전체복구용 폴더는 참고용이며 일괄 교체 대상이 아닙니다. v4.4.17을 설치하지 않은 프로젝트는 먼저 v4.4.17 설치 안내에 따라 기본 설정 모듈을 설치해야 합니다.

이번 INI.gs에서 기존 설정값은 빈 칸으로 유지합니다. 이전 파일에 아직 적용하지 않은 값이 있으면 메모한 뒤 연결설정 시트 C열로 옮기세요. 기존 속성·서명키·발송 기록은 삭제하지 않습니다. PC 보관용 INI.CS도 같은 변경을 담지만 평소 ID는 스프레드시트에서 관리합니다.

## 3. 사진 폴더 설정

1. 파일을 모두 저장합니다.
2. Apps Script에서 **setupFacilityConnectionSettings**를 실행합니다.
3. 운영 스프레드시트의 **연결설정** 탭을 엽니다.
4. 맨 아래 새로 추가된 **고장·공사 사진 저장 폴더** 행을 찾습니다. 기존 행과 작성 중인 C열 입력은 보존합니다.
5. 이 행의 노란 **C열**에 회사 Drive 폴더 주소 또는 폴더 ID를 넣습니다.
6. **previewFacilityConnectionSettings** 실행 → 해당 항목이 변경 예정인지 확인합니다.
7. **applyFacilityConnectionSettings** 실행 → D열 ID와 F열 적용 완료를 확인합니다.

별도 고장·공사 폴더가 지정되지 않았다면 현재 잔디 JPG 폴더를 함께 사용합니다. 앞으로 회사 폴더로 고정하려면 고장·공사 행에도 회사 폴더를 명시해 두세요. 잔디 달력도 같은 회사 폴더에 저장하려면 **잔디 달력 JPG 저장 폴더** 행 역시 같은 폴더를 지정하세요. 기존 잔디 설정이 이미 회사 폴더라면 바꿀 필요 없습니다.

관리자 확인 오류가 나면 기존 개인 계정으로 실행했는지, 스크립트 속성 JANDI_ADMIN_EMAIL이 그 계정인지 확인하세요. 오류를 피하려고 관리자 검사를 지우지 않습니다.

## 4. 기존 웹앱 배포 갱신

**배포 → 배포 관리 → 현재 배포 수정(연필) → 새 버전 → 배포**로 갱신합니다. 열어 둔 이전 웹앱 탭을 닫고 같은 /exec 주소로 다시 접속하세요. 오래된 탭은 이전 사진 저장 코드를 사용할 수 있습니다.

Google Drive 권한 요청이 나오면 기존 실행 계정으로 해당 프로젝트의 권한을 승인합니다. 회사 외부 공유나 조직 정책으로 쓰기가 차단되면 업로드가 실패하며 입력을 유지합니다. 실제 사용 환경에서 회사 폴더 쓰기 가능 여부를 확인해야 합니다.

## 5. 사용·확인

고장 사진 또는 공사 전·중·후 사진을 선택하고 저장합니다.

1. 기존 대기 중인 업무 변경의 서버 저장을 확인합니다.
2. 새 사진을 축소 JPG로 회사 Drive에 저장합니다.
3. 업로드 성공 후 사진 연결과 업무 기록을 서버에 저장합니다.
4. 모두 확인되면 창이 닫힙니다. 항목을 다시 열면 연결된 Drive 사진을 불러옵니다.

사진 저장 실패 시 입력창과 사진을 유지합니다. 업무 기록을 성공했다고 표시하지 않습니다. 재시도는 같은 요청과 파일명을 활용해 중복 생성을 줄입니다. 업로드는 성공했지만 업무 저장이 실패한 경우 Drive에 파일이 남을 수 있으며, 실제 저장 여부가 불명확하므로 자동 삭제하지 않습니다.

기존 고장·공사 사진은 업무 JSON 안의 이미지를 그대로 보여줍니다. 과거 사진 전체를 자동 이동하지 않습니다. 과거 사진을 새 사진으로 교체하면 새 사진부터 Drive에 저장됩니다. 등록창의 사진 삭제는 업무 연결만 지우며 Drive 원본 파일은 자동 삭제하지 않습니다. 기록을 삭제해도 회사 폴더의 파일은 남습니다.

고장·공사 사진은 **공개 링크로 공유하지 않습니다.** 기존 웹앱 접근 범위 안에서 서버가 저장된 기록의 사진을 확인하고 불러옵니다. 임의 Drive 파일 ID를 넣어 읽지 못하도록 사진 연결에 확인 서명을 붙입니다. 잔디 달력 JPG의 기존 링크 공유 방식은 별개로 유지합니다.

## 6. 백업·복구 시 달라지는 점

새 사진은 JSON 안에 사진 원본 대신 Drive 연결 정보가 들어갑니다. 따라서 **업무 JSON 백업만으로 새 사진 파일까지 복원되지는 않습니다.** 회사 Drive 폴더의 원본 사진도 보존해야 합니다.

프로젝트를 복사하거나 복구할 때 스크립트 속성 **REPAIR_PHOTO_SIGNING_KEY**도 별도로 보존해야 합니다. 이 값은 사진 연결 확인용으로 자동 생성됩니다. 공개 소스·업무 JSON에는 넣지 않습니다. 이 값을 지우거나 다른 프로젝트에서 새로 만들면 과거 연결 사진을 검증하지 못합니다. 기존 Drive 사진이 있는데 키가 없으면 새 키를 임의 생성하지 않고 복원 안내를 표시합니다.

보고 시트 작업과 Drive I/O는 원본 데이터 잠금 밖에서 수행합니다. 원본 업무 데이터·알 수 없는 필드·원래 사진·당직/복구 이력·수동 잔디 전송을 유지합니다. 메일과 NAS 기능은 추가하지 않았습니다.

개발 참고: [Google Drive Folder](https://developers.google.com/apps-script/reference/drive/folder), [File.getBlob](https://developers.google.com/apps-script/reference/drive/file#getBlob()).
