# v4.4.12 잔디 Incoming Webhook 당직변경 알림

이미지는 올리지 않습니다. ‘신청 저장·즉시 반영’으로 서버 저장이 성공하면 변경 월·현재 한국시간·변경 날짜·기존 웹앱 접속 링크를 잔디에 보냅니다. 원본 당직표와 기존 데이터는 보존합니다. **일반 Incoming Webhook만 사용하며 Team Incoming Webhook은 사용하지 않습니다.**

## 1. 적용 전 확인

- 이 설치 파일은 **v4.4.11 공사 사진·고장공사 분리 모듈까지 설치한 프로젝트**를 기준으로 합니다. 그 이전 버전이면 v4.4.10 → v4.4.11을 먼저 적용하세요.
- 웹앱에서 전체 JSON 백업을 내려받고 기존 Apps Script 코드도 보관하세요.
- 현재는 로컬·모의 전송 시험을 통과한 상태입니다. 사용자의 잔디 주소가 없으므로 실제 ‘나와의 대화’ 발송과 운영 배포는 수행하지 않았습니다.

## 2. 파일 4개 적용

| 제공 파일 | Apps Script 종류 | 작업 |
|---|---|---|
| Index.html | HTML | 기존 **Index** 전체 내용 교체 |
| DutyChangesUI.html | HTML | 기존 **DutyChangesUI** 전체 내용 교체 |
| JandiNotificationsUI.html | HTML | 새 파일 **JandiNotificationsUI** 추가 |
| JandiNotifications.gs | 스크립트 | 새 파일 **JandiNotifications** 추가 |

기존 파일은 내용을 뒤에 덧붙이지 말고 메모장에서 전체 복사 → Apps Script 해당 편집창 Ctrl+A → 붙여넣기로 교체합니다. 새 파일은 왼쪽 파일 옆 **+ → HTML 또는 스크립트**로 만듭니다. 확장자는 중복 입력하지 마세요.

**Code.gs, SPREADSHEET_ID, DutyChanges.gs와 나머지 기존 파일은 그대로 유지합니다.** HTML을 .gs 파일에 붙이면 Unexpected token '<' 오류가 납니다. 새 JandiNotifications.gs를 빼먹으면 includeJandiNotificationsUI_ 관련 오류가 납니다.

Ctrl+S로 저장한 후 **배포 → 배포 관리 → 기존 웹앱 → 연필 → 새 버전 → 배포**를 누릅니다. 기존 웹앱의 /exec 주소를 복사해 두세요. 새 배포를 만들거나 접근 권한을 임의로 넓힐 필요는 없습니다.

## 3. ‘나와의 대화’ 시험용 Incoming Webhook 만들기

잔디 PC 앱 또는 웹에서 본인의 **나와의 대화**를 먼저 엽니다. 해당 화면에서 **잔디 커넥트(플러그 모양) → Webhook 수신 / Incoming Webhook → 연동하기 또는 연동 추가**를 찾습니다. 메뉴 이름·위치는 잔디 환경과 권한에 따라 다를 수 있습니다.

연동 생성 화면에 수신 방을 고르는 항목이 있으면 **본인의 나와의 대화**인지 확인하세요. 연동 이름은 ‘시설관리 당직변경 시험’처럼 정합니다. 발급된 **Webhook URL**을 복사합니다.

일반 Incoming 주소 형식:

`https://wh.jandi.com/connect-api/webhook/…/…`

이 주소는 브라우저에서 보는 당직표 주소가 아니라 잔디가 메시지를 받는 비밀 연결 주소입니다. 채팅·소스 파일·GitHub에 붙이지 말고 아래 **스크립트 속성**에만 넣으세요.

**‘나와의 대화’에서 Incoming Webhook을 만들 수 없거나 수신 방 선택에 나타나지 않는다면 전체 직원 토픽을 시험 대상으로 대신 선택하지 마세요.** 현재 잔디 환경에서 개인 방 Incoming을 지원하는지 관리자 또는 잔디 앱의 1:1 문의로 확인하세요. 다른 방을 본인의 나와의 대화인 것처럼 안내하거나 Team 방식으로 자동 변경하지 않습니다. 일반 웹훅 주소만으로 앱이 실제 수신 방 이름을 조회·검증할 수는 없습니다.

공식 참고: [잔디 Incoming Webhook](https://support.jandi.com/en/articles/Receiving-Incoming-Webhooks-in-JANDI-56bacd47). [개인별 Incoming과 Team 방식의 구분](https://support.jandi.com/ko/articles/전체-멤버에게-Team-Incoming-Webhook을-발송하고-싶습니다-f281bf2e).

## 4. Apps Script에 시험 설정 입력

Apps Script 왼쪽 **톱니바퀴 → 프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**로 이동합니다. 이미 있는 시설관리 속성을 삭제하지 말고 아래 항목만 추가합니다.

| 속성 이름 | 입력할 값 |
|---|---|
| JANDI_ENABLED | `true` |
| JANDI_MODE | `test` |
| JANDI_ADMIN_EMAIL | Apps Script를 관리하는 본인의 **Google 계정 주소** |
| JANDI_TEST_WEBHOOK_URL | 본인 나와의 대화에서 발급한 Incoming Webhook URL |
| JANDI_WEB_APP_URL | 현재 시설관리 웹앱 주소. `https://script.google.com/macros/s/…/exec` 형식, 뒤의 ? 옵션 제외 |
| JANDI_TEST_MONTH | 시험 링크로 열 월. 예: `2026-11` (생략하면 현재 월) |
| JANDI_TEST_SITE | 본관은 `one`, 분관은 `two` (생략하면 본관) |

속성을 저장하세요. **JANDI_ADMIN_EMAIL은 관리 함수 실행자 확인용이며 이메일을 발송하지 않습니다.** 수신자 이메일·SMTP·메일 발송 설정은 없습니다.

JANDI_MODE는 아직 **test**로 유지합니다. 전체 토픽 주소는 이 단계에서 없어도 됩니다.

## 5. 개인 방에 시험 메시지 보내기

1. Apps Script 왼쪽 **JandiNotifications.gs**를 엽니다.
2. 상단 함수 선택에서 **sendJandiSelfTest**를 선택합니다.
3. **실행**을 누릅니다. 최초 실행 시 외부 서비스 연결 등 필요한 Google 권한 승인을 진행합니다.
4. 실행 로그에 `state: sent`와 ‘개인 시험 대상 전송 성공 응답’이 표시되는지 확인합니다.
5. 잔디 **나와의 대화**에서 메시지가 실제로 도착했는지 확인합니다. HTTP 성공 응답만으로 사용자가 읽었다고 판정하지는 않습니다.
6. 메시지의 접속URL을 눌러 당직변경화면의 해당 월·장소가 열리는지 확인합니다. 시험 메시지는 해당 월 1일을 링크 날짜로 사용하므로 당직이 없는 날이면 첫 당직일이 선택될 수 있습니다. 원본 월 당직표는 먼저 작성되어 있어야 합니다.
7. 웹앱의 당직변경화면에서 날짜를 골라 실제 변경을 저장합니다. 저장 성공 뒤 같은 개인 시험 방에 **실제 변경 날짜가 포함된 알림**이 오는지 확인합니다.

실제 알림 예시(시각은 발송 시점의 한국시간):

```text
11월 당직표 변경내용 <2026-10-28 15:30:00>
대상: 2026년 11월 · 본관
변경일: 2026-11-05
접속URL: https://script.google.com/macros/s/…/exec?page=dutyChanges&site=one&month=2026-11&date=2026-11-05
```

시험 연결 함수는 앞에 `[연결시험 · 나와의 대화]`를 붙입니다. 실제 변경 알림은 위 형식으로 보냅니다. 단순 날짜 조회·수정창 열기·내용이 그대로인 저장은 알림을 보내지 않습니다. 원본 배치로 되돌리기도 실제 변경 저장이므로 알립니다.

‘관리 계정으로 실행하세요’가 나오면 스크립트 속성의 관리 Google 계정과 실제 실행 계정이 같은지 확인하세요. ‘일반 Incoming Webhook’ 오류는 주소 형식·복사 누락·Team 주소 여부를 확인하세요. 오류 메시지나 실행 로그에는 비밀 웹훅 주소를 출력하지 않습니다.

## 6. 시험 완료 후 직원 전체 토픽으로 전환

1. 잔디에서 **직원 전체방으로 사용할 토픽**을 엽니다.
2. 그 토픽의 **잔디 커넥트 → Incoming Webhook → 연동 추가**로 별도 URL을 만듭니다.
3. Apps Script **스크립트 속성**에 **JANDI_TOPIC_WEBHOOK_URL**을 추가하고 그 토픽 URL을 넣습니다. 개인 시험 URL을 덮어쓰지 않습니다.
4. JandiNotifications.gs 상단 함수 선택에서 **enableJandiTopicMode**를 골라 실행합니다.
5. 개인 시험 전송 성공 기록과 전체 토픽 주소가 준비되어 있으면 JANDI_MODE가 **topic**으로 바뀝니다. 조건이 갖춰지지 않으면 전환을 거부합니다.
6. 웹앱의 **연결 상태 새로 확인**을 눌러 ‘직원 전체 토픽’으로 표시되는지 확인합니다.

이후 새로 저장하는 변경부터 전체 토픽에 알립니다. 이전 시험 메시지나 기존 모든 변경이력을 한꺼번에 발송하지 않습니다. 설정 변경만으로 재배포할 필요는 없습니다.

다시 개인 방에서 시험하려면 **enableJandiTestMode**를 실행합니다. 자동 알림을 끄려면 스크립트 속성 **JANDI_ENABLED**를 **false**로 바꿉니다. 개인 시험 주소나 웹앱 주소가 바뀌면 시험 성공 확인을 다시 받아야 합니다.

## 7. 저장·전송 실패 처리와 접근 권한

- 변경 데이터를 서버에 저장한 후 알림을 요청합니다. 서버 저장이 실패하면 발송하지 않습니다.
- 잔디 발송 실패를 당직표 저장 실패로 표시하지 않습니다. 당직표는 저장된 상태로 유지합니다.
- 같은 변경·발송 대상의 성공 기록을 보관하여 중복 클릭·응답 유실 뒤 결과 확인으로 다시 발송하지 않습니다.
- HTTP 4xx 등 명확한 실패는 설정을 고친 뒤 화면의 **전송 결과 확인·재시도**로 재시도할 수 있습니다. 통신 끊김·타임아웃·5xx 등 수신 여부가 불분명하면 중복 방지를 위해 자동 재발송하지 않습니다. 잔디에서 먼저 수신 여부를 확인하세요.
- 전송 중에 시험/전체 토픽 설정이 바뀌면 예전 요청을 새 방으로 임의 전환하지 않습니다.
- 저장 후 브라우저가 알림 요청을 보내기 전에 닫히면 알림 요청이 시작되지 않을 수 있습니다. 자동 재발송용 백그라운드 트리거는 설치하지 않습니다. 저장 뒤 전송 결과까지 확인한 후 닫으세요.
- 전송 결과 확인 버튼의 문맥은 현재 열린 화면에 유지합니다. 새로고침 후 과거 실패 알림을 일괄 재발송하는 기능은 없습니다. 90일을 초과한 변경의 발송도 제한합니다.
- 메시지에는 직원 실명이나 이미지가 없지만 기존 웹앱 URL은 전달됩니다. 링크는 **기존 웹앱의 접근 권한**을 그대로 따릅니다. 링크를 안다고 권한이 생기는 기능이 아니며, 기존 배포가 공개 상태라면 링크 역시 공개 앱을 가리킵니다. 접속 권한은 임의로 변경하지 않습니다. 직원 계정에서 실제 접속할 수 있는지 확인하세요.
- 링크는 당시 화면의 JPG·고정 스냅샷이 아니라 **접속 시점의 최신 변경 달력**을 엽니다.
- 웹훅 주소·관리 설정·발송 기록은 ScriptProperties에 있고 업무 JSON 백업이나 GitHub 소스 복원에 포함되지 않습니다. 운영 자료를 지우거나 새 시트를 만들지 않습니다.

## 8. 개발 파일과 검증 범위

전용 서버는 **JandiNotifications.gs**, 화면은 **JandiNotificationsUI.html**입니다. jandi-notifications-ui.js 수정 후 **node build-jandi.cjs**로 HTML을 생성합니다. 당직변경 UI는 duty-changes-ui.js 수정 후 **build-changes.cjs**, 마지막에 **build-jandi.cjs**를 실행하여 include 순서를 보장합니다. Index 전체 재생성은 build-release.cjs → build-changes.cjs → build-jandi.cjs 순서입니다. 고장·공사 모듈 include도 유지해야 합니다.

모의 서버에서 일반 Incoming 형식·한국시간·접속 링크·저장된 이력만 발송·시험 후 토픽 전환·관리자 제한·중복 방지·HTTP 실패·비밀 주소 비노출·외부 호출 중 원본 잠금 해제를 확인했습니다. 로컬 Edge에서 서버 저장 후 발송, 발송 응답 유실과 상태 확인, 저장 실패 시 미발송, 원본 보존, 링크의 월·장소·날짜 이동, 모바일 360/390px을 확인했습니다. 기존 저장·당직변경·공사 사진 회귀도 확인합니다.

**실제 잔디 메시지 수신과 실제 운영 배포는 연결 정보 입력 후 확인해야 합니다.**

공식 참고: [잔디 Incoming Webhook](https://support.jandi.com/en/articles/Receiving-Incoming-Webhooks-in-JANDI-56bacd47), [Apps Script URL 매개변수 읽기](https://developers.google.com/apps-script/guides/html/reference/url).
