# v4.4.7 당직인원관리 전용 파일 분리

같은 Apps Script 프로젝트 안에서 당직 기능을 전용 파일로 나눴습니다. 이번에는 **기존 파일 3개 교체 + 새 파일 3개 추가**가 필요합니다. 이전 두 파일 교체 방식과 다릅니다.

## 1. 먼저 백업

전체 JSON, Apps Script 소스, 시트 사본을 보관하세요. **기존 Code.gs의 SPREADSHEET_ID 값도 따로 복사**해 두세요. 이번에도 기존 스프레드시트를 계속 사용합니다. 기존 자료를 초기화하지 않습니다.

## 2. 파일을 넣을 위치

| 제공 파일 | Apps Script 종류 | 작업 | 담당 기능 |
|---|---|---|---|
| Code.gs | 스크립트 | 기존 전체 교체 | 기존 연결 ID·웹앱 입구·보고 시트 |
| Index.html | HTML | 기존 Index 전체 교체 | 기존 업무 화면·당직 화면 연결 |
| DutyManagement.gs | 스크립트 | 기존 전체 교체 | 당직 생성·공휴일·월 자동작성 |
| DutyRosterCore.gs | 스크립트 | 새로 추가 | 순번·자동/고정 대체·삭제/복구 |
| FacilityStorage.gs | 스크립트 | 새로 추가 | 원본 저장·버전 검사·짧은 잠금 |
| DutyManagementUI.html | HTML | 새로 추가 | 당직인원관리 전용 화면 |

1. **이번에는 Code.gs도 교체**합니다. 교체 후 본인의 기존 SPREADSHEET_ID가 유지되는지 확인하고, 다르면 백업한 기존 ID로 바꿔 주세요.
2. Index와 DutyManagement.gs도 이번 파일 내용으로 전체 교체합니다. 예전 내용을 남긴 채 뒤에 덧붙이지 않습니다.
3. 왼쪽 **+ → 스크립트**로 DutyRosterCore와 FacilityStorage를 만들고 각 .gs 파일 내용을 붙여 넣습니다. 편집기가 붙이는 확장자를 중복 입력하지 마세요.
4. **+ → HTML**로 DutyManagementUI를 만들고 해당 HTML 내용을 넣습니다.
5. CalendarReminders.gs와 NoEndRepeats.gs는 유지합니다. 기존 서버 인증키와 트리거도 계속 사용합니다.
6. Ctrl+S → 배포 → 배포 관리 → 기존 배포의 연필 → 새 버전 → 배포합니다.
7. 기존 웹앱 주소를 새로고침합니다.

**Index와 DutyManagementUI는 HTML 파일입니다.** HTML 내용을 Code.gs 등에 넣으면 Unexpected token '<' 오류가 납니다. 나머지 네 파일은 스크립트입니다. 제공한 파일 이름 그대로 사용해 주세요.

이제 당직 화면은 DutyManagementUI.html에서, 자동매칭 계산은 DutyRosterCore.gs에서 관리합니다. 처음 구조를 옮길 때는 여섯 파일을 모두 맞춰야 합니다. 이후 당직 화면만 수정할 때는 큰 Index 전체를 바꾸지 않아도 됩니다.

## 3. 작성 버튼·잠금 처리

작성 버튼을 한 번 누르면 즉시 ‘작성 중…’으로 바뀌고 비활성화합니다. 작성 응답과 서버 새로고침이 끝날 때까지 다시 실행하지 않습니다. 완료 또는 실패 안내 후 다시 활성화합니다. 이미 작성된 세 달은 기존 표를 유지하는 조회만 수행합니다.

원본 JSON·버전 확정은 공통 잠금 안에서 처리하고, 오래 걸리는 보고용 시트 갱신은 잠금 밖에서 처리합니다. 보고 시트를 동시에 쓰지 않도록 별도의 진행 표시를 사용합니다. 보고 실패와 원본 저장 실패도 구분합니다. 클라우드 상태에서 보고용 시트 재시도를 안내할 수 있습니다.

원본 저장 자체가 혼잡하면 ‘다른 저장 작업 진행 중’으로 안내할 수 있으므로 잠시 후 다시 시도하세요. 원본 저장·버전 충돌 검사를 제거하거나 실행 제한을 무조건 우회하는 방식이 아닙니다.

## 4. 장소별 직원창

상단 날짜 옆에서 본관을 고르고 직원·소속 등록을 열면 본관 직원만, 분관을 고르면 분관 직원만 표시합니다. 이름 추가 입력란과 시작 인원도 해당 장소의 것만 보입니다. 미배정 직원 관리는 아래 접힌 항목에서 펼칠 수 있습니다.

미배정 직원은 고정 점심대체자로 선택 가능하며, 선택만으로 소속을 변경하지 않습니다. 소속 이동 버튼을 명시적으로 누른 경우에만 이동합니다.

## 5. 분관 공통 점심대체 순번

BRANCH_DEMO_02·BRANCH_DEMO_06의 당직일을 날짜순으로 합쳐 **한 개의 공통 순번**을 진행합니다.

**BRANCH_DEMO_01 → BRANCH_DEMO_03 → BRANCH_DEMO_04 → BRANCH_DEMO_07 → BRANCH_DEMO_01 → …**

다음 달에는 전월 다음 대체자부터 이어집니다. 대체 불필요일과 고정 대체자 배치일에는 자동 순번을 소모하지 않습니다. 본관의 자동·고정 배치는 유지합니다.

### 기존 분관 표를 맞추는 방법

1. 분관과 적용할 조회 월을 선택합니다.
2. **점심당직·휴무 설정 → 분관 대체 순서 예시 적용**을 누릅니다.
3. 네 명의 순서와 BRANCH_DEMO_02·BRANCH_DEMO_06 자동매칭, 적용 시작일을 확인하고 저장합니다.
4. 조회 월부터 점심대체 정보만 다시 계산하고 일반 당직자·다른 장소는 유지합니다. 변경 전 표는 내부 이력에 보관합니다.

예시 버튼은 등록된 이름을 찾습니다. 없는 이름을 임의 생성하거나 다른 이름을 바꾸지 않습니다. 이번에 알려 주신 이름은 **BRANCH_DEMO_07**이며, 이전에 적힌 다른 이름과 자동으로 동일인 처리하지 않습니다. 실제 등록명을 확인하거나 체크 목록에서 직접 선택하세요.

기존 날짜에 개별 지정한 대체자가 남아 있다면 현재 자동매칭 규칙과 공통 순서로 다시 계산합니다. 실제 운영 자료를 원격으로 읽어 오류 원인을 확정한 것은 아닙니다.

### 대체자가 바뀔 때

- 직원·소속 등록의 **점심대체 순번 참여** 또는 설정창의 체크 목록에서 참여자를 고릅니다.
- 선택 순서는 아래 순번 목록의 ↑/↓로 조정합니다. 새로 체크한 사람은 뒤에 추가합니다.
- 후보·순서 변경 시 적용 시작일과 ‘기존 표에 점심대체만 적용’을 확인하고 저장합니다.
- 직원창에서 후보나 대체 방식을 바꾸면 변경 일수를 확인한 뒤 해당 월 이후 점심대체만 재계산합니다. 일반 당직자는 유지합니다.

‘점심대체 필요’는 대체를 받아야 할 당직자이고, ‘점심대체 순번 참여’는 대신 근무할 후보입니다. 같은 사람을 같은 날 당직자와 대체자로 중복 배치하지 않습니다.

## 6. 전체삭제·취소

장소와 조회 월을 고르고 **전체삭제 (조회 월)**를 누르면 그 장소의 한 달 표만 지웁니다. 직원·설정·다른 달·다른 장소·일반 업무 자료는 유지합니다. 확인창에서 대상 월과 일수를 먼저 보여줍니다.

**전체삭제 취소**로 삭제 직전 표를 복구합니다. 삭제한 월은 자동 생성에서 제외합니다. 직접 ‘전달·이번달·다음달 작성’을 누르면 다시 생성합니다. 새 표가 이미 있으면 취소로 덮어쓰지 않습니다. 과거 Google 캘린더 작성 완료 알림까지 삭제하지는 않습니다.

## 7. 확인 범위

모의 서버에서 원본 확정·버전 충돌·보고 실패 시 원본 유지, 보고 작성 중 잠금 해제·동시 저장·최신 보고 반영, 삭제/취소·자동 재생성 방지를 확인했습니다.

로컬 Edge에서 중복 클릭 차단·새로고침까지 비활성·실패 후 재활성, 장소별 직원창, 미배정 고정 대체자, 분관 공통 네 명 순서·참여자 체크 변경·다음 달 연결, 본관과 일반당직 보존, 모바일 360/390px 화면을 확인했습니다.

실제 운영 배포·공휴일 API·휴대전화 알림·이번 개정의 PDF 편집 재검증은 실행하지 않았습니다. GitHub에는 직원 실명과 운영 ID를 제거한 사본을 별도로 보관합니다.
