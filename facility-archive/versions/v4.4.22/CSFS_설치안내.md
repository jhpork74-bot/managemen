# v4.4.22 CSFS 월별 등록게시판·회사 Drive 사진

이름은 **CSFS**입니다. 등록할 때 선택한 월을 기준으로 보관합니다. 완료예정일이 다른 달이어도 등록 월에 남습니다. +등록 창은 1번 입력란으로 시작하며 +항목 추가마다 제목/대상자/완료예정일/사진 입력란이 한 개씩 추가됩니다. 각 입력란과 저장된 카드는 삭제할 수 있습니다.

화면은 CSFSManagementUI.html, 모델과 사진 연결 서비스는 CSFSManagement.gs에 분리했습니다. 업무 데이터는 기존 원본 JSON의 csfs.months에 별도로 저장하며 공통 저장 잠금·버전 충돌·백업을 유지합니다. 사진 원본은 회사 Drive 폴더에 저장하고 업무에는 서명된 연결만 보관합니다.

사용자의 명시적 요청에 따라 이 공개 사본을 GitHub에 보관합니다. 운영용 원본은 로컬에서 보존합니다. 새 회사 폴더 적용·운영 웹앱 배포는 아직 직접 수행하지 않았습니다. 설치 후 확인해야 합니다.

## 1. 먼저 백업

웹앱 전체 백업, 현재 스크립트/HTML, 스크립트 속성을 PC에 보관하세요. 기존 운영 프로젝트를 사용하며 새 프로젝트를 만들지 않습니다. 기존 회사 사진·사진 확인키·관리자 이메일·잔디 주소를 삭제하지 않습니다.

기존 INI.gs의 INI_LEGACY_SPREADSHEET_ID를 메모하세요. 새 INI.gs에서도 반드시 **현재 운영 시트 ID를 유지**해야 합니다. 회사 사진 폴더 ID를 원본 스프레드시트 ID 칸에 넣지 마세요.

## 2. 파일 8개 적용 — v4.4.20 또는 v4.4.21 기준

| 종류 | 이름 | 작업 |
|---|---|---|
| 스크립트 | INI.gs | 기존 내용 교체. 운영 시트 ID 유지 |
| 스크립트 | ConnectionSettings.gs | 기존 내용 교체 |
| 스크립트 | RepairPhotoStorage.gs | 기존 내용 교체. 사진 공통 저장/읽기 유지 |
| 스크립트 | CSFSManagement.gs | 새 스크립트 CSFSManagement 생성 후 전체 붙여넣기 |
| HTML | Index.html | 기존 HTML Index 내용 교체 |
| HTML | PopupBehaviorUI.html | 기존 HTML 내용 교체 |
| HTML | JandiNotificationsUI.html | 기존 HTML 내용 교체. 상단 재전송 버튼 이동 포함 |
| HTML | CSFSManagementUI.html | 새 HTML CSFSManagementUI 생성 후 전체 붙여넣기 |

스크립트는 + → **스크립트**, HTML은 + → **HTML**로 만듭니다. .html을 .gs에 넣으면 Unexpected token '<' 오류가 납니다. 이름의 대소문자와 CSFS 철자를 맞추세요. 같은 파일을 중복 생성하지 않습니다. Code.gs 등 표에 없는 파일은 유지합니다.

Index에 다른 운영 커스텀 기능을 별도로 추가한 경우 기존 소스를 먼저 보관하세요. 이 묶음은 제공된 최신 버전을 기준으로 합니다. 원본 업무 자료나 다른 프로젝트의 설정을 덮어쓰는 작업은 아닙니다.

## 3. 기존 스프레드시트에 회사 사진 폴더 넣기

1. 모두 저장하고 기존 관리자 개인 계정 또는 등록된 회사 계정으로 **setupFacilityConnectionSettings**를 실행합니다.
2. 기존 스프레드시트의 **연결설정** 탭을 엽니다.
3. 새 **CSFS 사진 저장 폴더** 행을 찾습니다.
4. 노란 C열에는 사용자가 알려준 다음 ID가 미리 들어 있습니다.

```text
CSFS_FOLDER_PLACEHOLDER
```

5. 이 값이 실제 회사 **사진 저장 폴더**인지 확인합니다. 기존 업무 시트 ID와는 별개입니다.
6. **previewFacilityConnectionSettings** 실행 후 변경 예정 항목을 확인합니다. 다른 행에 작성 중인 값이 있으면 함께 표시되므로 원하는 변경만 있는지 확인하세요.
7. **applyFacilityConnectionSettings** 실행 → D열과 F열의 적용 완료를 확인합니다.

현재 실행/배포 계정에 이 회사 폴더의 **편집자 권한**이 필요합니다. 폴더가 아닌 파일 ID거나 접근 권한이 없으면 검사를 통과하지 않으며 기존 설정은 보존됩니다. 시트에 값을 표시하는 것만으로 적용되지는 않습니다.

설정이 없는 상태에서는 CSFS 사진 업로드를 중단하고 폴더 지정 안내를 표시합니다. 다른 개인 Drive 폴더에 임의 저장하지 않습니다. 고장·공사 및 잔디 폴더 설정은 따로 유지합니다.

## 4. 배포 갱신

저장 → 배포 → 배포 관리 → 기존 웹앱 수정 → **새 버전** → 배포. 이전 탭을 닫고 평소 /exec 주소로 다시 접속합니다.

## 5. CSFS 사용법

메뉴의 **CSFS**를 누릅니다. 메뉴는 고장·공사관리 뒤에 추가됩니다.

1. 조회 월을 선택합니다. 이 월의 저장된 카드만 표시됩니다.
2. **+등록**을 누릅니다. 1번 항목이 나옵니다.
3. 제목, 대상자, 완료예정일을 입력합니다.
4. 필요한 경우 **사진등록**으로 촬영하거나 **갤러리**에서 사진을 고릅니다. 촬영 취소 후 갤러리는 직접 눌러 선택할 수 있습니다.
5. **+항목 추가**를 누를 때마다 다음 번호가 하나씩 나타납니다.
6. 불필요한 입력란은 **이 항목 삭제**로 제거합니다.
7. 저장하면 사진을 회사 폴더에 먼저 저장하고 등록 내용의 서버 저장까지 확인한 뒤 창이 닫힙니다.

저장된 카드의 **수정/삭제**를 사용할 수 있습니다. 사진이 없는 카드의 **사진등록**도 수정창을 엽니다. 사진을 누르면 크게 볼 수 있습니다. 월을 바꾸면 선택 월의 목록으로 갱신됩니다. 번호는 해당 월의 표시 순서이며 삭제 후 다시 1번부터 정리됩니다.

입력값과 사진 처리 중에는 관련 버튼을 막습니다. 저장 실패 시 완료했다고 표시하지 않고 입력창을 유지합니다. 취소/바깥 클릭은 기존 공통 팝업 규칙을 따르며 미저장 변경은 확인합니다. CSFS는 자동 잔디 발송이나 알림을 만들지 않습니다.

## 6. 사진·복구 주의사항

사진은 선택 사항이며 회사 Drive에 축소 JPG로 저장됩니다. 공개 링크 공유를 하지 않습니다. 기존 고장·공사 사진과 같은 공통 서명 확인키를 사용하므로 **REPAIR_PHOTO_SIGNING_KEY**를 보존해야 합니다.

업무 JSON 백업에는 사진 원본이 아닌 연결 정보가 들어갑니다. 회사 Drive 원본과 스크립트 속성도 따로 보관해야 합니다. 항목 삭제/사진 교체는 연결을 바꾸며 Drive 원본을 자동 삭제하지 않습니다. 사진 업로드 후 업무 저장이 실패하면 파일이 남을 수 있으며 수신/저장 여부가 불명확한 파일을 자동 삭제하지 않습니다.

## 7. 함께 포함한 버튼 이동

잔디로 이미지 전송 오른쪽에 같은 달력 다시 전송을 묶어 표시합니다. 원래 성공 기록이 있을 때 나타나는 조건과 확인창/중복 방지는 유지합니다. 이미 v4.4.21을 적용했다면 동일 배치입니다. 실제 잔디 이미지 미리보기를 확인했다고 단정하지 않습니다.

## 검증 범위

로컬·모의 Google Sheets/Drive/RPC·Edge에서 등록 월 기준 조회, 한 항목씩 추가/삭제, 수정·서버 저장, 사진 업로드/재조회, 실패 시 입력 유지·재시도, 원래 데이터/다른 월 보존, 360/390px 화면 및 기존 기능 회귀를 확인합니다. 실제 회사 폴더 쓰기·운영 배포·휴대폰 카메라 동작은 설치 후 확인이 필요합니다.

## 공개 보관 사본의 설정

실제 직원 이름·원본 시트 ID·회사 Drive 폴더 ID는 가명과 자리표시자로 바꿨습니다. 설치 시 기존 운영 시트 ID와 실제 회사 폴더 ID를 복원해야 합니다. ScriptProperties·사진 원본·운영 JSON·권한·트리거는 이 보관본에 포함되지 않습니다. CSFS_FOLDER_PLACEHOLDER는 실제 폴더가 아닙니다. 사진 확인키는 기존 속성 백업을 별도로 보존하세요.
