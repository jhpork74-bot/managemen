# v4.4.14 잔디 수동 이미지 전송 + 고장·공사 버튼 정렬

## 바뀐 기능

1. 당직변경화면 제목 바로 옆에 **잔디로 이미지 전송** 버튼을 추가했습니다. 날짜별 ‘신청 저장·즉시 반영’은 당직표 저장만 수행합니다. 여러 날짜를 계속 수정·저장한 뒤 새 버튼을 눌러 선택한 본관/분관·월의 최신 달력 전체를 한 번에 전송합니다.
2. 고장·공사 추가/수정 팝업의 **취소 / 저장**을 오른쪽 한 줄로 배치하고 두 버튼 사이에 약 다섯 글자 너비 간격을 두었습니다. 저장 상태 문구는 버튼 줄 위에 따로 표시합니다.

이 업데이트는 기존 v4.4.12 잔디 연동 파일 구조를 기준으로 하며 v4.4.13 이미지 서버 파일과 고장·공사 누락 연결 파일도 포함합니다. 원본 당직표·직원·변경이력·고장·공사·기존 사진·Webhook 설정·시트 연결 ID를 유지합니다. 먼저 전체 JSON과 코드를 백업하세요.

## 설치 파일: HTML 3개 + 스크립트 3개

| 제공 파일 | Apps Script 종류 | 적용 |
|---|---|---|
| DutyChangesUI.html | HTML | 기존 DutyChangesUI 전체 내용 교체 |
| JandiNotificationsUI.html | HTML | 기존 JandiNotificationsUI 전체 내용 교체 |
| RepairsManagementUI.html | HTML | 기존 RepairsManagementUI 전체 내용 교체. 없으면 HTML 추가 |
| JandiNotifications.gs | 스크립트 | 기존 JandiNotifications 전체 내용 교체 |
| JandiCalendarImages.gs | 스크립트 | 기존 파일 전체 교체. 없으면 스크립트 추가 |
| RepairsManagement.gs | 스크립트 | 기존 파일 전체 교체. 없으면 스크립트 추가 |

각 파일을 메모장으로 열고 Ctrl+A → Ctrl+C로 전체 복사한 뒤, Apps Script 해당 파일 편집창에서 Ctrl+A → Ctrl+V로 전체 교체합니다. 새 파일은 왼쪽 파일 옆 **+ → HTML / 스크립트**로 생성하고 확장자는 이름에 중복 입력하지 않습니다. HTML을 스크립트에 넣지 마세요.

**현재 Index, Code.gs, DutyChanges.gs 및 다른 파일·스크립트 속성은 유지합니다.** Index를 이전 버전 파일로 교체할 필요가 없습니다. 특히 DutyChangesUI와 JandiNotificationsUI 두 파일을 모두 교체해야 제목 옆 버튼과 저장/전송 분리가 정상 동작합니다.

## 이미지 준비와 배포

1. Ctrl+S로 전체 저장합니다.
2. 이미 enableJandiCalendarImages를 실행해 이미지 폴더를 준비했다면 기존 설정을 사용합니다. 아직이라면 **JandiCalendarImages.gs → 함수 enableJandiCalendarImages → 실행 → Google Drive 권한 승인**을 한 번 진행합니다.
3. 이 함수는 새로 생성하는 JPG만 **링크가 있는 모든 사용자: 뷰어**로 공유해 잔디가 사진을 읽게 합니다. 기존 Drive 자료·시트·웹앱의 권한은 변경하지 않습니다.
4. **배포 → 배포 관리 → 현재 사용하는 웹앱 → 연필 → 새 버전 → 배포**를 누릅니다.
5. 기존 웹앱 탭을 닫고 배포 관리의 /exec 주소로 다시 접속합니다. 오래 열린 탭에는 예전 자동 전송 코드가 남을 수 있습니다.

JANDI_ADMIN_EMAIL, JANDI_ENABLED, JANDI_MODE, 시험/전체 토픽 주소와 기존 이미지 폴더 설정은 그대로 유지합니다.

## 사용 방법

1. 당직변경화면에서 본관 또는 분관과 월을 고릅니다.
2. 날짜를 눌러 사람을 수정하고 **신청 저장·즉시 반영**을 누릅니다. 이때는 잔디에 발송하지 않습니다.
3. 다른 날짜도 원하는 만큼 수정·저장합니다. 원본 당직인원관리 표는 유지하고 변경 화면에만 반영합니다.
4. 수정이 끝나면 변경 팝업을 닫고 제목 옆 **잔디로 이미지 전송**을 누릅니다.
5. 서버 저장 완료를 확인한 뒤 해당 월 전체의 최신 JPG를 만들어 현재 설정된 잔디 개인 시험 방 또는 전체 토픽에 전송합니다. 웹앱 접속 링크는 표시하지 않습니다.

전송 준비·처리 중에는 중복 클릭과 조회 대상 혼동을 막기 위해 전송 버튼과 당직 화면의 날짜 수정·월·장소 변경을 잠시 막고, 작업이 끝나면 다시 사용할 수 있습니다. 실패해도 저장된 변경은 유지합니다.

- 같은 달력을 다시 눌러도 같은 마지막 변경이 이미 전송됐다면 성공 기록만 확인하고 중복 발송하지 않습니다.
- 추가 수정·저장 후 새 전송 버튼을 누르면 새 이미지가 전송됩니다.
- 변경이력이 없는 월은 먼저 변경을 저장하라는 안내를 표시합니다.
- 전송 실패 후 ‘전송 결과 확인·재시도’는 같은 변경의 결과를 확인합니다. 그 사이 추가 수정이나 조회 대상 변경이 있으면 제목 옆 버튼으로 최신 달력을 보내도록 안내합니다.
- 네트워크가 끊겨 잔디 수신 여부가 불분명한 경우에는 자동 재발송하지 않습니다. 잔디에서 먼저 수신 여부를 확인하세요.
- 이미지의 ‘N번째 변경’은 저장된 월/장소별 변경이력 회차이며 잔디 발송 횟수와 다를 수 있습니다. 여러 번 수정한 뒤 한 번 전송하면 그 마지막 변경 회차가 표시됩니다.
- 오래된 잔디 메시지나 Drive 이미지를 삭제·교체하지 않습니다. 새 저장본은 별도 JPG입니다.
- 브라우저를 전송 도중 닫으면 완료 여부를 확인할 수 없으므로 전송 결과를 확인한 후 닫으세요.

## 검증·범위

로컬 Edge와 모의 RPC에서 두 날짜를 수정·저장해도 전송 0회, 새 버튼 클릭 시 최신 월 달력 1회 전송, 추가 수정 후 다시 명시적으로 전송, 같은 저장본 중복 방지, 응답 유실 후 재확인, 빈 월·저장 충돌 시 미전송, 원본 당직표 보존을 확인했습니다. 360/390px에서도 고장·공사 취소/저장이 같은 높이 한 줄이고 간격이 확보되는지 확인했습니다. 이미지 생성·공유·잔디 서버는 모의 시험이며 실제 운영 배포와 잔디 이미지 수신은 설치 후 확인해야 합니다.

개발용 소스는 duty-changes-ui.js → build-changes.cjs, jandi-notifications-ui.js / jandi-calendar-canvas.js → build-jandi.cjs, repairs-markup.html / repairs.css / repairs-ui.js → build-repairs.cjs로 생성합니다. 최종 빌드 순서는 build-changes.cjs → build-jandi.cjs로 include 순서를 유지합니다. jandi-manual-ui.js는 초기 작성 보조본이며 이후 수정 기준은 jandi-notifications-ui.js입니다.
