# v4.4.10 저장 개선·당직변경화면

v4.4.7 이상 전용 파일 구성을 사용하는 프로젝트에 적용합니다. 저장 안정화(v4.4.9)를 함께 포함한 설치 묶음입니다. 운영 자료와 기존 연결 ID는 유지합니다.

## 파일 적용

먼저 현재 전체 JSON과 Apps Script 코드를 백업하세요.

| 제공 파일 | 종류 | 작업 |
|---|---|---|
| Index.html | HTML | 기존 Index 내용 전체 교체 |
| FacilityStorage.gs | 스크립트 | 기존 내용 전체 교체 |
| CalendarReminders.gs | 스크립트 | 기존 내용 전체 교체 |
| DutyManagementUI.html | HTML | 기존 내용 전체 교체·최신 이름 표시 유지 |
| DutyChanges.gs | 스크립트 | 새로 추가 |
| DutyChangesUI.html | HTML | 새로 추가 |

새 파일은 Apps Script 왼쪽 +에서 종류를 선택하고 이름을 각각 DutyChanges, DutyChangesUI로 입력합니다. 확장자를 편집기가 붙이면 중복 입력하지 마세요. 기존 파일은 뒤에 추가하지 않고 편집창 전체를 교체합니다.

**Code.gs, 기존 SPREADSHEET_ID, DutyRosterCore.gs, DutyManagement.gs, NoEndRepeats.gs는 유지합니다.** 아직 전용 파일 분리 버전을 설치하지 않았다면 v4.4.7 분리 설치부터 완료해야 합니다.

Ctrl+S → 배포 → 배포 관리 → 기존 배포의 연필 → 새 버전 → 배포 후 기존 웹앱을 새로고침합니다. HTML을 .gs에 붙이면 Unexpected token '<' 오류가 납니다.

## 당직변경화면

‘당직인원관리’ 바로 뒤에 새 메뉴가 나타납니다. 작성된 원본 당직표가 기준표로 표시되며, 원본에 새로운 월표가 생기면 그 월도 조회할 수 있습니다. 초기 표시 때문에 원본 데이터를 별도로 저장하거나 수정하지 않습니다.

1. 장소와 조회 월을 고릅니다.
2. 변경할 날짜를 누릅니다.
3. 새 당직자를 선택합니다. 그 직원의 기존 자동/고정 규칙에 맞춰 점심대체자를 함께 불러옵니다.
4. 필요하면 점심대체 필요 체크와 대체자를 직접 수정합니다.
5. **신청 저장·즉시 반영**을 누르고 서버 저장 완료를 확인합니다.

승인 단계와 변경 사유 입력은 없습니다. 원본 당직표는 그대로 두고 변경 화면의 일정만 바꿉니다. 변경된 날짜는 강조 표시합니다.

## 변경이력

선택한 날짜의 이력은 **이전 사람 / 현재 사람** 두 칸만 표시합니다. 점심대체자가 있으면 당직자와 한 묶음으로 표시합니다. 변경 사유·변경 시각·신청자 항목은 표시하지 않습니다.

예: DEMO_A · 점심 DEMO_B → DEMO_C · 점심 직원 라

새 당직자에게 대체가 필요 없으면 이전 대체자는 남기지 않습니다. 여러 차례 바꾸면 직전 배치에서 다음 배치로 이어진 이력을 남깁니다. ‘원본 배치로 되돌리기’를 누르면 변경 적용을 취소하고 그 되돌림도 이력에 남깁니다.

원본이 나중에 다시 작성되어 기존 변경 신청의 기준 배치와 달라지면 ‘원본도 변경됨 · 확인 필요’를 표시합니다. 원본 월표를 삭제하면 그 월의 변경 화면도 기준표가 없다고 표시하며, 저장된 변경이력 자체를 지우지는 않습니다. 실제 다른 직원·다른 날짜에 변경을 옮기는 기능은 포함하지 않습니다.

당직변경 전용 계산·연결은 DutyChanges.gs, 전용 화면은 DutyChangesUI.html에서 관리합니다. 변경 정보는 기존 JSON의 dutyChanges에 별도로 저장하므로 전체 백업·복원에도 포함됩니다. 원본 자동 당직 순번은 변경 신청으로 소모하지 않습니다.

## 시트 저장 개선

원본 저장을 먼저 확인하고 보고 시트·일정 알림 갱신은 묶어 처리합니다. 연결·잠금 오류는 최대 3회 자동 재시도하며, 같은 요청을 다시 보내도 원본 버전을 중복 증가시키지 않습니다. 오프라인은 임시본을 유지하고 재접속 시 재시도합니다. 다른 기기와 버전 충돌이 나면 자동 덮어쓰기 없이 멈춥니다.

클라우드 상태에는 원본 저장 확인과 보고 시트 대기를 구분해 표시합니다. 앱을 닫아도 보고 시트를 갱신하려면 클라우드 상태의 **앱을 닫아도 보고 시트 자동갱신**을 한 번 누르거나 Apps Script에서 **installFacilityStorageMaintenance**를 실행해 권한을 승인하세요. 약 5분 간격 확인 트리거를 중복 없이 설치합니다. 이 설정 전에는 보고 시트 갱신이 다음 접속까지 늦어질 수 있습니다.

## 검증·제약

모의 서버·로컬 Edge에서 응답 유실 뒤 동일 요청 재시도, 재시도 중 추가 변경, 잠금·오프라인·충돌·보고 실패, 원본 보존, 변경 배치의 저장 즉시 반영, 두 사람 묶음 이력, 불필요한 이전 대체자 제거, 되돌림·모바일 360/390px 표시를 확인했습니다.

실제 운영 시트 저장 속도 측정, 운영 웹앱 배포, 실제 공휴일 API·휴대전화 알림 확인은 수행하지 않았습니다. 인터넷·서비스 오류를 무조건 없애는 기능은 아닙니다. 이메일 발송 기능은 추가하지 않았습니다.

GitHub에는 직원 실명·실제 운영 ID를 제거한 사본을 보관합니다. GitHub의 Code.gs 자리표시자를 그대로 운영 프로젝트에 붙이지 말고 기존 본인 ID를 유지하세요.
