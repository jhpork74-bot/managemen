# v4.4.11 고장·공사관리 분리 / 공사 전·중·후 사진

이 업데이트는 v4.4.10(저장 안정화·당직변경화면)이 설치된 프로젝트를 기준으로 합니다. 아직 설치하지 않았다면 v4.4.10을 먼저 적용하세요. 기존 연결 ID·시트·운영 데이터·트리거는 그대로 사용합니다. 운영 배포는 직접 수행하지 않았습니다.

## 먼저 백업

웹앱에서 전체 JSON 백업을 내려받고 Apps Script의 기존 코드를 복사해 보관하세요. 시트나 기존 스크립트를 삭제하지 마세요.

## 적용할 파일은 3개입니다

| 파일 | Apps Script 종류 | 적용 |
|---|---|---|
| Index.html | HTML | 기존 **Index**의 내용 전체 교체 |
| RepairsManagementUI.html | HTML | **새 HTML** 파일, 이름은 RepairsManagementUI |
| RepairsManagement.gs | 스크립트 | **새 스크립트** 파일, 이름은 RepairsManagement |

1. 압축을 풀고 Index.html을 메모장으로 엽니다. Ctrl+A → Ctrl+C로 전체 내용을 복사하세요.
2. Apps Script의 기존 **Index**를 선택하고 편집창 안에서 Ctrl+A → Ctrl+V로 전체 교체하세요.
3. 파일 옆 **+ → HTML**을 선택합니다. 이름은 **RepairsManagementUI**로 입력합니다. 기본 내용을 지우고 제공된 RepairsManagementUI.html의 전체 내용을 붙여 넣으세요.
4. 다시 **+ → 스크립트**를 선택합니다. 이름은 **RepairsManagement**로 입력합니다. 기본 함수를 지우고 제공된 RepairsManagement.gs의 전체 내용을 붙여 넣으세요.
5. 확장자는 편집기가 붙이므로 .html/.gs를 이름에 중복 입력하지 마세요. 이미 같은 파일이 있다면 새로 만들지 말고 내용을 교체하세요.
6. Ctrl+S로 저장합니다. **Code.gs와 연결 ID, 나머지 기존 파일은 수정하지 않습니다.**
7. **배포 → 배포 관리 → 현재 웹앱 배포 → 연필 → 버전에서 새 버전 → 배포**를 선택합니다.
8. 기존 웹앱 주소를 새로고침합니다. 이전 화면이 남으면 탭을 닫고 다시 열어 보세요.

HTML을 .gs 스크립트에 넣으면 Unexpected token '<' 오류가 납니다. includeRepairsManagementUI_ is not defined가 나오면 새 RepairsManagement.gs가 같은 프로젝트에 있는지 확인하세요.

## 사진 사용

1. **고장·공사관리 → 공사처리**를 엽니다.
2. 공사를 추가하거나 기존 공사 카드를 누릅니다.
3. **공사 전 / 공사 중 / 공사 후** 각각에 사진을 1장씩 첨부합니다. 한 공사에 단계별 총 3장을 넣을 수 있습니다.
4. **사진 촬영**을 누르면 후면 카메라 촬영을 우선 요청합니다. 촬영을 취소하면 갤러리 자동 열기를 시도할 수 있는 환경에서는 시도하고, 그 외에는 **갤러리에서 선택** 버튼을 강조합니다. 이 버튼을 한 번 눌러 사진을 골라 주세요.
5. 각 단계에서 사진 교체·삭제가 가능하며 사진 미리보기를 누르면 크게 볼 수 있습니다.
6. 맨 아래 **저장**을 누르고 서버 저장 완료를 기다립니다. 사진 처리·저장 중에는 중복 작업을 막습니다. 사진만 선택한 뒤 취소하면 기록에 반영되지 않습니다.

기존 고장 사진은 유지합니다. 기존 공사에 photo 필드로 저장된 사진은 **기존 사진 (단계 미지정·보존)**으로 표시하며 임의로 전/중/후에 분류하거나 삭제하지 않습니다. 새 단계별 사진은 같은 공사 기록의 workPhotos.before/during/after에 추가합니다. 기타 기존 필드도 보존합니다. 사진은 최대 긴 변 960px JPEG로 자동 축소하고 기존 전체 저장 용량 검사를 유지합니다. 원본 화질의 사진 보관소는 아닙니다.

## 휴대전화·PC 제약

- capture="environment"는 카메라 우선 요청입니다. 실제 카메라 실행·카메라/파일 선택 메뉴는 휴대전화와 브라우저가 결정합니다. PC에서는 보통 파일 선택창이 열립니다.
- 카메라 취소 뒤 다른 파일 선택창을 자동으로 열려면 새 사용자 동작이 필요할 수 있습니다. 일부 환경은 취소 이벤트도 제공하지 않습니다. 그래서 **갤러리에서 선택** 버튼을 항상 제공합니다. 앱으로 돌아왔을 때 버튼을 강조하는 보조 처리도 포함했습니다.
- 갤러리 버튼은 촬영 강제 옵션 없이 시스템의 사진·파일 선택창을 요청합니다. 실제 표시 명칭은 기기마다 다릅니다.
- JPG/PNG 등을 사용하세요. 브라우저가 읽지 못하는 HEIC 등은 오류를 안내하고 기존 사진을 유지합니다.
- 파일 분리만으로 Apps Script의 JSON 저장 용량이 늘어나지는 않습니다. 전체 사진 용량이 커지면 기존 용량 안내에 따라 관리해야 합니다.

참고: [MDN capture](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture), [파일 선택 취소 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/cancel_event), [showPicker와 사용자 동작 요구](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/showPicker).

## 분리 구조와 유지보수

- **RepairsManagementUI.html**: 고장·공사 화면, 입력창, 카드 CSS, 전/중/후 사진 처리·표시·저장 연결
- **RepairsManagement.gs**: 고정된 전용 HTML을 불러오는 함수. 새 시트나 별도 저장소를 만들지 않습니다.
- **Index.html**: 전용 모듈 include와 기존 공통 메뉴·저장 처리 유지. 고장·공사 전용 본문·입력창·계산/사진 코드·CSS는 이동했습니다.
- 개발용 분리 소스: repairs-markup.html / repairs.css / repairs-core.js / repairs-ui.js. 수정 후 node build-repairs.cjs로 설치용 HTML을 생성합니다. 이 개발용 파일들은 Apps Script에 별도 추가하지 않습니다.
- 전체 Index를 다시 생성할 경우 기존 build-release.cjs → build-changes.cjs 순서를 지키고 includeRepairsManagementUI_()가 남아 있는지 확인하세요. repairs 모듈은 build-repairs.cjs로 생성합니다.

## 검증

전체 GS 및 HTML 내 JavaScript 구문 검사, 데이터 병합 시험, 로컬 Edge와 모의 Google RPC에서 기존 사진·미지정 필드 보존, 단계별 저장·교체·삭제, 입력 취소, 이미지 오류, 서버 저장 실패 시 입력창 유지, 360/390px 표시를 확인했습니다. 기존 당직변경화면과 저장 재시도·오프라인·충돌 보호도 회귀 확인했습니다.

실제 운영 시트·웹앱에는 배포하지 않았습니다. 실제 Android/iPhone 카메라 실행·취소·갤러리 전환은 사용 기기에서 추가 확인해야 합니다. 이메일 기능을 추가하지 않았습니다.
