# v4.4.13 저장할 때마다 잔디에 변경 달력 JPG 전송

v4.4.12 Incoming Webhook 메시지 수신까지 설정한 프로젝트의 업데이트입니다. 사용자가 개인 시험 메시지 수신을 확인했습니다. 새 이미지 첨부는 로컬·모의 시험만 완료했으며 실제 Google Drive·잔디 이미지 표시는 설치 후 확인해야 합니다.

## 적용 파일 3개

먼저 기존 코드와 전체 JSON을 백업하세요.

| 제공 파일 | Apps Script 종류 | 작업 |
|---|---|---|
| JandiNotifications.gs | 스크립트 | 기존 내용 전체 교체 |
| JandiNotificationsUI.html | HTML | 기존 내용 전체 교체 |
| JandiCalendarImages.gs | 스크립트 | 새 파일 **JandiCalendarImages** 추가 |

1. 파일을 메모장으로 열고 Ctrl+A → Ctrl+C로 복사합니다.
2. Apps Script에서 대응하는 기존 파일을 골라 편집창 Ctrl+A → Ctrl+V로 **전체 교체**합니다.
3. 새 JandiCalendarImages는 왼쪽 **파일 옆 + → 스크립트**를 눌러 만들고 기본 코드를 지운 뒤 붙여 넣습니다. .gs 확장자를 중복 입력하지 않습니다.
4. Ctrl+S로 저장합니다. **Index·Code.gs·연결 ID·다른 파일·기존 스크립트 속성은 그대로 둡니다.** 기존 관리자·Incoming 시험/토픽 주소를 다시 입력할 필요는 없습니다.

## 이미지 전송 준비: 한 번만 실행

1. 새 **JandiCalendarImages.gs**를 엽니다.
2. 상단 함수 선택에서 **enableJandiCalendarImages**를 선택합니다.
3. **실행**을 누르고 필요한 Google Drive 권한을 승인합니다. JANDI_ADMIN_EMAIL에 등록된 관리 계정으로 실행해야 합니다.
4. 실행 로그에서 ‘달력 JPG 전송 준비 완료’를 확인합니다.

이 함수는 내 Drive에 **시설관리_잔디_당직변경이미지** 폴더를 만들고 폴더 ID·활성화 설정을 스크립트 속성에 자동 저장합니다. 같은 함수를 다시 실행하면 기존 폴더를 사용합니다. 이미지 폴더 ID를 직접 입력할 필요는 없습니다.

**새로 생성한 달력 JPG 각각은 ‘링크가 있는 모든 사용자: 뷰어’로 공유합니다.** 잔디가 로그인 없이 사진을 읽어야 하기 때문입니다. 기존 Drive 자료·폴더·시트·웹앱의 권한은 변경하지 않습니다. 회사 Google Workspace에서 외부 링크 공유를 막는 경우에는 이 방식으로 표시할 수 없습니다. 이때는 오류를 안내하고 이미지를 잔디에 보내지 않습니다.

## 기존 배포 업데이트

**배포 → 배포 관리 → 현재 웹앱 → 연필 → 새 버전 → 배포**를 선택합니다. 기존 웹앱 탭을 새로고침하세요. 새 권한 승인·배포 반영을 마치지 않으면 이미지 준비가 되지 않았다는 안내가 나올 수 있습니다.

## 사용 순서

1. 웹앱 **당직변경화면**에서 본관/분관·월·날짜를 고릅니다.
2. 새 당직자와 필요한 점심대체자를 선택합니다.
3. **신청 저장·즉시 반영**을 누릅니다.
4. 원본 서버 저장이 성공한 뒤 서버에 저장된 월 당직표를 다시 읽습니다.
5. 해당 장소·월 전체를 고정 폭 JPG로 만듭니다. 모바일에서도 잘리지 않도록 달력 데이터를 이미지용으로 그리는 방식이며 운영체제 전체 화면을 캡처하지 않습니다.
6. JPG를 Drive에 저장하고 잔디가 로그인 없이 실제 이미지로 조회할 수 있는지 확인합니다.
7. 현재 설정한 개인 시험 방 또는 직원 전체 토픽에 **변경 월·한국시간·변경 날짜·변경 회차와 달력 이미지**를 보냅니다.

**웹앱 접속 URL은 메시지에 표시하지 않습니다.** 잔디는 imageUrl 첨부 방식을 사용하므로 이미지 자체를 누르면 잔디/이미지 보기 동작이 나타날 수 있습니다. 클립보드에 복사해서 붙이는 방식이 아니라 Incoming Webhook의 이미지 미리보기입니다. JPG 파일 자체는 Drive에 남습니다.

메시지 예시:

```text
11월 당직표 변경내용 <2026-10-28 21:30:00>
대상: 2026년 11월 · 본관
변경일: 2026-11-05
변경: 1번째 (해당 장소·월)
[변경된 월간 당직표 이미지]
```

이미지에서 노란색은 변경 반영 날짜, 테두리는 이번 변경 날짜입니다. 당직자와 점심대체가 필요한 날의 대체자를 함께 표시합니다. 기존 변경사항도 해당 월 달력에 함께 보입니다.

## 1번째·2번째·그 이후 변경

- **실제 변경 저장 1회마다 별도 JPG와 메시지 1개**를 만듭니다.
- 같은 날짜를 다시 바꾸거나 다른 날짜를 바꿔도 새 이력이므로 각각 발송합니다.
- 이전 JPG를 덮어쓰지 않으므로 이전 메시지의 이미지가 나중에 바뀌지 않습니다.
- 회차는 **본관/분관별·월별 저장된 변경이력 순서**입니다. 설치 전 이력이 5개라면 다음 변경은 6번째로 표시될 수 있습니다. 이미 발송한 횟수와는 다를 수 있습니다.
- 내용을 바꾸지 않고 저장하면 새 이력·이미지·메시지를 만들지 않습니다.
- 원본 배치로 되돌리기도 실제 변경이므로 회차와 알림을 남깁니다.
- 전송 결과 확인을 다시 누르는 것은 같은 변경을 중복 발송하지 않습니다. 전송 결과를 확인할 때 이미 성공했다면 JPG도 새로 만들지 않습니다.

## 실패 시 처리

- 이미지 생성·저장·잔디 전송이 실패해도 **완료된 당직 변경 저장은 유지**됩니다.
- 캡처 준비 후 서버 달력이 바뀌었다면 최신 달력을 다시 읽어 한 번 재생성합니다.
- Drive 미리보기가 아직 준비되지 않았으면 잔디에 보내지 않고 재시도를 안내합니다. 같은 이미지 파일이 준비되어 있으면 재사용합니다.
- 통신이 끊겨 잔디 수신 여부를 알 수 없거나 5xx 응답이면 자동 재발송하지 않습니다. 잔디에서 수신 여부를 확인하세요.
- 화면의 **전송 결과 확인·재시도**는 같은 변경의 결과를 확인하며 명확한 실패에만 다시 발송합니다. 새로고침 뒤 과거 실패 목록을 자동 복구·일괄 재발송하지는 않습니다.
- 브라우저를 저장 직후 닫으면 JPG 생성·요청이 시작되지 않을 수 있습니다. 전송 결과까지 확인한 뒤 닫으세요.
- Drive 용량은 사용하며 자동으로 기존 이미지 파일을 삭제하지 않습니다. 직접 지우거나 공유를 끄면 이전 잔디 이미지가 나중에 안 보일 수 있습니다.
- 이미지 조회용 Drive 썸네일 주소는 잔디에서 실제 표시되는지 운영 환경에서 확인해야 합니다. 외부 이미지 조회를 사전 확인하지만 잔디의 미리보기 처리·캐시까지 보장하지는 않습니다. Drive 확인 후에도 잔디에서 안 보이면 오류 화면을 알려주세요.

## 시험 방·전체 토픽

기존 **JANDI_MODE**와 시험/토픽 Incoming 주소를 유지합니다. 개인 시험 상태라면 처음에는 그 방으로 이미지가 갑니다. 실제 이미지 도착을 확인한 다음 기존 **enableJandiTopicMode**로 직원 전체 토픽으로 전환하세요. 기존 텍스트 시험 성공 기록을 유지합니다. 이미 전체 토픽 상태라면 새 변경이 바로 그 토픽으로 전송됩니다.

이미지 전송을 중단하려면 **disableJandiCalendarImages**를 관리 계정으로 실행합니다. 기존 이미지와 당직표는 삭제하지 않으며, 이후 자동 알림은 이미지 준비 필요 상태로 멈춥니다. 웹앱 링크 전송으로 자동 되돌리지 않습니다. 모든 잔디 자동 알림을 끄려면 기존 JANDI_ENABLED를 false로 설정합니다.

## 개발·검증

서버는 JandiNotifications.gs와 JandiCalendarImages.gs, 화면·JPG 렌더링은 JandiNotificationsUI.html에 있습니다. jandi-calendar-canvas.js / jandi-notifications-ui.js 수정 후 **node build-jandi.cjs**를 실행합니다. jandi-image-notify.js는 JandiNotifications.gs의 notifyDutyChangeJandi 원본 조각이므로 수정 시 최종 GS에도 반영해야 합니다.

모의 Drive/잔디에서 변경별 다른 이미지·회차·중복 방지·실패 시 파일 재사용·공유 거부·이미지 조회 실패 시 미발송·서버 저장 잠금 해제·시험/토픽 전환을 확인했습니다. 로컬 Edge에서 3회 연속 실제 변경 후 서로 다른 JPEG 생성, 저장 실패 시 미전송, 원본 보존, 모바일 360/390px을 확인하고 생성 JPG를 육안으로 확인했습니다. 실제 운영 이미지 수신·Drive 생성은 수행하지 않았습니다.

공개 GitHub에는 실제 직원 이름·운영 ID·Webhook 주소·운영 이미지·업무 JSON을 올리지 않습니다. 원본 개발·설치 파일의 기존 연결 설정은 보존합니다. 메일·NAS 기능을 추가하지 않습니다.
