# v4.4.15 1개씩 복구 + 팝업 바깥 클릭 닫기

현재 v4.4.14 구성에 적용하는 업데이트입니다. 원본 직원·당직표·변경이력·고장/공사·사진·Webhook·연결 ID는 보존합니다. 적용 전 현재 코드와 전체 JSON을 백업하세요.

## 압축파일 구성과 적용

HTML과 스크립트가 헷갈리지 않도록 폴더를 나눴습니다. 파일을 메모장으로 열고 내용을 전체 복사하여 Apps Script의 해당 종류 파일에 붙여 넣습니다. 컴퓨터에서 HTML을 여는 것만으로는 설치되지 않습니다.

| 폴더 / 제공 파일 | Apps Script 종류 | 적용 방법 |
|---|---|---|
| HTML_4개 / Index.html | HTML | 기존 Index 내용 전체 교체 |
| HTML_4개 / DutyChangesUI.html | HTML | 기존 DutyChangesUI 내용 전체 교체 |
| HTML_4개 / DutyManagementUI.html | HTML | 기존 DutyManagementUI 내용 전체 교체 |
| HTML_4개 / PopupBehaviorUI.html | HTML | 새 HTML, 이름 **PopupBehaviorUI** |
| 스크립트_GS_2개 / DutyChanges.gs | 스크립트 | 기존 DutyChanges.gs 내용 전체 교체 |
| 스크립트_GS_2개 / PopupBehavior.gs | 스크립트 | 새 스크립트, 이름 **PopupBehavior** |

새 파일은 Apps Script 왼쪽 파일 옆 **+ → HTML 또는 스크립트**로 추가합니다. .html/.gs 확장자는 중복 입력하지 않습니다. 이미 같은 이름·종류의 파일이 있다면 내용을 교체하고 중복 파일을 만들지 마세요. **Code.gs와 기존 연결 ID·스크립트 속성은 유지**합니다. 다른 모듈은 그대로 둡니다.

DutyChanges.gs의 첫 줄은 `var DutyChangesCore=(function(){`입니다. DutyChangesUI.html은 `<style>`로 시작합니다. HTML을 .gs에 넣으면 Unexpected token '<' 오류가 납니다. PopupBehavior는 HTML과 스크립트가 각각 필요합니다.

6개 파일을 모두 넣고 **Ctrl+S → 배포 → 배포 관리 → 기존 웹앱 → 연필 → 새 버전 → 배포**를 선택하세요. 기존 탭을 닫고 배포 관리의 /exec 주소로 다시 접속합니다. includePopupBehavior_ 오류가 나면 PopupBehavior.gs가 같은 프로젝트에 있는지, PopupBehaviorUI 파일을 찾지 못하면 HTML을 추가했는지 확인하세요.

## 1개씩 복구

당직변경화면의 **잔디로 이미지 전송** 바로 옆에 **1개씩 복구**가 표시됩니다.

1. 본관/분관과 조회 월을 선택합니다.
2. ‘1개씩 복구’를 한 번 누르면 **그 장소·월의 가장 최근 변경 1건**을 바로 이전 배치로 복구하고 서버 저장합니다. 현재 선택한 날짜만 복구하는 기능이 아닙니다.
3. 다시 누르면 그다음 최근 변경을 복구합니다. 복구 작업 자체를 다시 취소하는 식으로 두 상태가 반복되지 않습니다.
4. 같은 날을 A→B→C로 바꿨다면 C→B, 다음 클릭은 B→A입니다. 다른 날짜를 여러 개 바꿨다면 마지막 수정 날짜부터 거꾸로 한 건씩 복구합니다.
5. 당직자와 점심대체자를 함께 복구합니다. 점심대체가 없었던 상태도 그대로 복구합니다.

복구 내용은 즉시 화면에 반영한 뒤 서버 저장 결과를 확인합니다. 성공 표시까지 기다리세요. 처리 중 버튼과 월/장소 변경을 막아 연속 클릭으로 여러 건이 한꺼번에 진행되지 않게 합니다. 복구 가능한 기록이 없으면 버튼이 비활성화됩니다.

기존 변경이력을 삭제하지 않고 ‘이전 사람 / 현재 사람’ 두 칸에 복구 결과도 남깁니다. 내부에 복구 대상 식별 정보를 기록하여 복구 완료한 작업을 다시 복구 후보로 잡지 않습니다. 다른 장소·월의 변경과 원본 당직인원관리 표는 그대로 유지합니다. 과거 버전의 이력도 복구에 사용하며, 이전 원본표가 다시 작성되어 안전하게 비교할 수 없는 경우에는 자동 복구를 멈추고 확인을 안내합니다.

기존 ‘원본 배치로 되돌리기’는 그 날짜를 원본으로 돌리는 기능이고, ‘1개씩 복구’는 중간 변경을 한 단계씩 되짚는 기능입니다. 원본 배치로 되돌렸던 작업도 이력이 남아 있으면 한 단계 복구할 수 있습니다. 이 기능에는 별도 ‘다시 실행’ 버튼은 없습니다.

**변경 저장과 복구 모두 잔디에 자동 전송하지 않습니다.** 수정·복구를 끝낸 뒤 사용자가 ‘잔디로 이미지 전송’을 눌러야 최신 월 달력을 보냅니다. 복구도 새 저장 이력이므로 그 뒤 수동 전송하면 복구된 달력의 새 JPG가 전송됩니다. 이미 보낸 잔디 메시지나 JPG를 삭제·변경하지는 않습니다.

## 팝업 밖을 눌러 닫기

- 업무 등록, 점검항목, 재고, 발주·입출고, 고장·공사, 직원·당직 설정, 당직변경, 사진 보기 등 **이 웹앱이 만든 HTML 팝업**에 공통 적용합니다.
- 팝업 상자 밖의 배경을 클릭하거나 터치하면 취소와 같이 닫힙니다. 저장 버튼을 대신 누르는 동작이 아닙니다.
- 입력이나 사진 변경이 없으면 바로 닫힙니다.
- 저장하지 않은 입력·사진 변경이 있으면 버릴지 확인합니다. 확인에서 취소하면 입력창과 내용이 유지됩니다.
- 팝업 안을 클릭하거나 안에서 밖으로 드래그하는 동작만으로 닫히지 않습니다.
- 사진 확대처럼 팝업이 겹쳐 있으면 가장 위의 팝업 한 개만 닫힙니다.
- 서버 저장·사진 처리·당직 처리 중에는 바깥 클릭으로 닫히지 않습니다. 작업이 끝난 뒤 다시 닫을 수 있습니다.
- 브라우저 자체의 확인/권한 승인 창, 휴대전화 카메라·파일 선택창은 이 HTML 기능의 적용 대상이 아닙니다.

새 PopupBehavior 모듈은 창 닫기 동작만 관리하며 업무 데이터를 쓰지 않습니다. 저장 실패·오프라인·충돌 시 기존 임시본 보호도 유지합니다.

## 검증과 미검증 범위

Node 모의 시험에서 최근 3건 순차 복구, 복구 기록 건너뛰기, 새 변경 후 복구, 당직자/점심대체자 및 이전 메타데이터 복원, 원본/다른 장소/월/알 수 없는 필드 보존, 과거 이력 복구, 원본 재작성 시 중단을 확인했습니다.

로컬 Edge와 모의 Google RPC에서 버튼 위치, 빠른 두 번 클릭으로 1건만 복구, 저장 ACK, 자동 잔디 미전송, 바깥 클릭·내부 클릭·드래그, 미저장 글/사진 보호, 겹친 팝업, 저장 중 닫힘 방지, 직원창 처리 보호, 360/390px 표시를 확인했습니다. 기존 수동 이미지 전송·고장공사 버튼 정렬·저장 회귀도 확인합니다. 실제 운영 배포와 휴대전화 터치·카메라·실제 잔디 전송은 수행하지 않았습니다.

개발 시 duty-changes-core.js / duty-changes-ui.js 수정 후 build-changes.cjs, JANDI는 build-jandi.cjs, 공통 팝업은 마지막에 build-popups.cjs를 실행합니다. DutyManagementUI의 비동기 작업 보호 함수는 ui.js에도 유지합니다. 이전 버전의 전체 파일로 되돌리면 복구 메타데이터가 남더라도 이전 화면에는 1개씩 복구 버튼이 나타나지 않습니다.
