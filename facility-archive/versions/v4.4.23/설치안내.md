# 시설관리 v4.4.23 — 저장 충돌 복구 개선

v4.4.22의 CSFS·회사 Drive 사진·당직·잔디 수동 전송 기능을 유지한 개선본입니다. 로컬·모의 검증본이며 운영 웹앱에 자동 배포되지 않습니다.

## v4.4.22 설치자는 두 파일만 교체

1. 기존 웹앱의 ‘월간 통계·백업’에서 전체 JSON을 다운로드합니다. 미저장 내용이 있으면 ‘클라우드 상태’의 ‘보관된 미전송 임시본 다운로드’도 먼저 실행합니다.
2. 사용 중인 PC·휴대전화의 웹앱 창을 모두 닫습니다. Apps Script 편집기에서 현재 Index와 FacilityStorage의 내용을 각각 별도 파일로 복사해 보관합니다.
3. ZIP을 압축 해제하고 `1_v4.4.22_사용자_교체2개` 폴더를 엽니다.
4. Apps Script 왼쪽의 **HTML 파일 Index**를 엽니다. 내용을 전체 선택 후 ZIP의 **Index.html 전체 내용**으로 교체합니다. HTML을 Code.gs 등 스크립트 파일에 붙여 넣지 않습니다.
5. 왼쪽의 **스크립트 파일 FacilityStorage.gs**를 엽니다. 내용을 전체 선택 후 ZIP의 **FacilityStorage.gs 전체 내용**으로 교체합니다. 같은 이름의 파일을 추가하지 않습니다.
6. 저장 버튼 또는 Ctrl+S로 저장합니다. INI·연결설정·ScriptProperties·폴더 ID·관리자 이메일은 수정할 필요가 없습니다. 별도 초기화 함수나 설치 트리거를 실행하지 않습니다.
7. 오른쪽 위 ‘배포’ → ‘배포 관리’를 누릅니다. 지금 사용하는 웹앱 배포를 선택하고 연필 모양 수정 버튼을 누릅니다.
8. 버전에서 **새 버전**을 선택하고 설명에 `v4.4.23 저장 충돌 복구 개선`을 입력한 뒤 배포합니다. 실행 계정·접근 권한은 기존 설정을 유지합니다.
9. 기존 `/exec` 주소로 새 창을 엽니다. 화면 맨 아래 **v4.4.23 · 저장 충돌 복구 개선** 표시와 상단 저장 상태를 확인합니다.
10. 먼저 실제로 완료한 업무 한 건을 체크하고 ‘원본 저장 확인’으로 바뀌는지 확인합니다. 이후 다른 기기에서 최신 데이터 불러오기로 결과를 확인합니다.

두 파일은 반드시 함께 적용합니다. 한 파일만 바꾸면 최신 버전 확인이나 충돌 복구 기능이 작동하지 않을 수 있습니다.

## 지금 v4.4.15로 되돌린 경우

`1_v4.4.22_사용자_교체2개`만 설치하지 않습니다. 새 Index는 CSFS 등 최신 모듈도 포함하므로 서버에 해당 파일이 없으면 include 함수 오류가 납니다.

`2_전체코드_참고_구버전복귀시확인`에는 HTML 7개·GS 15개 전체 세트를 넣었습니다. 기존 프로젝트의 소스와 설정을 먼저 보관하고 같은 이름의 파일은 교체, 없는 파일은 해당 형식으로 추가해야 합니다.

특히 기존 운영 Code.gs의 스프레드시트 ID와 기존 INI.gs의 `INI_LEGACY_SPREADSHEET_ID`를 확인하고 현재 사용하는 원본 시트를 유지해야 합니다. 회사 사진 폴더 ID를 원본 시트 ID에 넣지 않습니다. 이미 사용 중인 INI.gs는 이 버전에서 변경되지 않았으므로 기존 파일을 유지합니다. v4.4.15에는 INI가 없다면 전체 세트의 INI를 추가하되 승계 원본 시트 ID를 기존 운영 ID로 맞춥니다.

연결설정·RepairPhotoStorage 등 v4.4.16 이후 기능이 없는 상태라면 기존 v4.4.22의 CSFS 설치안내도 함께 확인합니다. 사진 연결키·웹훅·관리자 계정 등 기존 ScriptProperties는 지우지 않습니다. 코드만으로 Drive 파일·권한·비밀 설정·트리거가 복구되지는 않습니다.

## 달라진 저장 동작

- 서로 다른 업무 영역의 수정은 기준 자료와 서버 내용을 비교해 합칩니다.
- 업무 배열의 항목·순서가 유지된 상태에서 서로 다른 업무를 완료 체크한 경우에도 합칩니다.
- 같은 업무를 양쪽에서 다르게 수정하거나, 연결된 재고·당직·점검 자료가 겹치면 저장을 멈추고 입력을 보존합니다. 버전 검사를 제거하지 않습니다.
- ‘최신 변경 확인·합치기’에서 겹친 업무 영역별로 서버 내용 또는 내 변경을 선택합니다. 상세 내용도 펼쳐 볼 수 있습니다. 선택하지 않은 양쪽 자료는 기기 보관본으로 남깁니다.
- 충돌한 임시본의 원래 기준 버전을 보존합니다. 이전 버전에서 만들어 기준 자료가 없는 임시본은 자동 병합하지 않습니다. 먼저 백업 후 서버 자료와 비교합니다.
- 화면 복귀 및 약 1분 간격으로 서버 버전 변경을 조회합니다. 조회만으로 작성 중인 내용을 교체하지 않습니다.
- 최근 16개 실제 저장 요청의 처리 결과를 보관해 저장 응답 유실 후 재시도를 보호합니다. 이 범위를 넘은 요청도 버전 검사를 우회하지 않습니다.
- 연속 충돌에 대한 자동 합치기 시도는 제한됩니다. 계속 겹치면 ‘최신 변경 확인·합치기’로 확인합니다.

## 충돌이 남을 때

열려 있는 입력창 내용을 먼저 보존한 후 닫고 상단의 ‘최신 변경 확인·합치기’를 누릅니다. 같은 업무 영역에서 충돌했다면 상세 내용을 보고 선택합니다. 이때 ‘내 변경 사용’은 해당 영역 전체를 선택한다는 뜻입니다.

기준 자료가 없는 과거 임시본은 ‘내 미저장 내용 백업’을 다운로드한 뒤 ‘내 임시본 보관 후 서버 내용 사용’으로 최신 자료를 확인하고 필요한 항목을 다시 입력합니다. 오래된 JSON을 전체 복원하여 덮어쓰지는 않습니다.

## 복구 및 검증 범위

문제가 생기면 보관한 두 원본 파일을 함께 되돌리고 기존 배포에 새 버전을 지정합니다. 시트·사진·서명키·영수증·이력은 삭제하지 않습니다. 이번 코드는 기존 JSON 구조와 저장 슬롯을 유지하며 데이터 일괄 변환을 하지 않습니다.

18개 저장 복구 시나리오, 기존 저장·CSFS·사진·당직변경·한 건 복구 모의 검증을 통과했습니다. 로컬 브라우저에서 서로 다른 완료 체크의 합치기, 같은 업무 충돌 안내·비교창·서버 내용 선택을 확인했습니다. 실제 운영 배포·Google 서비스에서의 다중 기기 저장·모바일 실기기 검증은 아직 하지 않았습니다.

공개 사본에는 실제 원본 시트·회사 폴더 ID, 직원 이름, 비밀 설정, 운영 JSON과 사진이 없습니다. 설치 시 기존 운영 설정을 복원해야 합니다. 진단 스크립트의 CSFS_FOLDER_PLACEHOLDER도 실제 폴더 ID로 맞춰야 합니다. 코드 보관은 운영 배포·데이터·사진·권한·트리거 복원을 대신하지 않습니다.
