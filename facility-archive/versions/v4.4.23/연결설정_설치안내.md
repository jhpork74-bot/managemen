# v4.4.16 연결 설정 통합·잔디 달력 사진 저장 폴더 교체

기존 v4.4.15 기준 업데이트입니다. 로컬·모의 서버·Edge 회귀 검사 완료이며, 실제 운영 배포·Drive 쓰기·잔디 이미지 수신은 아직 확인하지 않았습니다. 새 폴더 ID를 전달받지 않아 현재 연결은 교체하지 않았습니다.

## 1. 무엇을 관리하나요?

| 항목 | 설정 이름 | 관리 방법 |
| --- | --- | --- |
| 업무 데이터 원본 스프레드시트 | SPREADSHEET_ID | INI 상단. 기존 데이터가 있으면 별도 이관 필요 |
| 잔디 달력 JPG 저장 폴더 | JANDI_IMAGE_FOLDER_ID | INI 상단에서 변경 가능 |
| 업무 사전알림 캘린더 | facilityReminderCalendarId | INI 상단. 기존 이벤트 연결이 있으면 별도 이관 필요 |
| 당직표 작성 알림 캘린더 | dutyNotificationCalendarId | INI 상단. 기존 이벤트 연결이 있으면 별도 이관 필요 |
| 웹앱 실행 주소 | JANDI_WEB_APP_URL | INI 상단, 쿼리 없는 /exec 주소 |

직원·업무·반복그룹·사진 파일·캘린더 이벤트의 개별 ID, 저장 버전·잠금·발송 영수증은 업무 데이터 또는 시스템 내부 상태입니다. 설정으로 옮기거나 임의로 바꾸지 않습니다. 공개 API 서비스 주소나 PDF 라이브러리 주소는 사용자 계정 ID가 아닙니다.

고장·공사 사진은 현재 업무 JSON 안에 압축 이미지로 저장됩니다. 이 버전의 Drive 폴더 변경 대상은 **잔디로 보내는 당직 달력 JPG**입니다. 고장·공사 사진의 저장 구조 변경이나 기존 사진 이동은 하지 않습니다.

## 2. INI.CS와 INI.gs의 차이

요청하신 **INI.CS**는 PC 보관용 설정 원본입니다. 내용은 JavaScript이며 C# 프로그램이 아닙니다. Apps Script가 직접 실행하는 파일은 **INI.gs**입니다. 두 파일은 동일한 내용으로 제공하며 프로젝트에는 INI 스크립트 하나만 만듭니다. HTML로 만들지 마세요.

PC에서 INI.CS를 수정했다면 내용을 Apps Script의 INI.gs에 붙여 넣으세요. 자동 동기화는 아닙니다. 개발 도구를 사용하는 경우 `node build-ini.cjs`로 INI.gs를 생성할 수 있습니다. Apps Script에서만 수정했다면 그 내용을 PC의 INI.CS에도 보관해 두세요.

Google 공식 설명: [프로젝트 파일 형식](https://developers.google.com/apps-script/guides/projects), [스크립트 속성](https://developers.google.com/apps-script/guides/properties).

## 3. 먼저 백업하세요

1. 웹앱의 전체 백업을 다운로드합니다.
2. Apps Script의 기존 Code.gs 등 교체할 파일을 PC에 복사해 둡니다.
3. 프로젝트 설정의 기존 스크립트 속성을 본인 PC에 별도로 기록합니다. 비밀 연결 주소를 공개 저장소에 올리지 마세요.
4. 현재 Code.gs의 `SPREADSHEET_ID`를 확인합니다. 제공된 INI.gs의 `INI_LEGACY_SPREADSHEET_ID`가 **현재 운영 ID와 같은지 확인**하세요. 다르면 운영 ID를 INI의 이 항목에 옮긴 뒤 교체합니다. 현재 연결을 승계하는 용도입니다.
5. 직원들이 저장·당직표 작성·잔디 전송 중이 아닐 때 적용하세요.

## 4. Apps Script에 넣을 파일

압축파일의 `1_교체할_스크립트_GS_6개` 폴더에서 기존 같은 이름의 파일 내용을 각각 모두 교체합니다.

- Code.gs
- FacilityStorage.gs
- CalendarReminders.gs
- DutyManagement.gs
- JandiNotifications.gs
- JandiCalendarImages.gs

다음은 `2_새로추가할_스크립트`의 **INI.gs**입니다.

1. 왼쪽 파일 옆 **+** → **스크립트** 선택.
2. 파일 이름을 **INI**라고 입력합니다. `.gs`는 자동으로 붙습니다.
3. 처음 들어 있는 예시 함수를 지우고 INI.gs 전체를 붙여 넣습니다.
4. 저장합니다.

이번 업데이트에 **HTML 교체는 없습니다.** Index 및 각 UI HTML, DutyChanges/PopupBehavior/RepairsManagement 등 나머지 기존 모듈을 유지하세요. 전체복구용 폴더는 참고용으로 포함했으며 일괄 교체 대상이 아닙니다.

## 5. 새 Google Drive 폴더 지정

1. Google Drive에서 앞으로 JPG를 저장할 폴더를 엽니다.
2. 주소가 `https://drive.google.com/drive/folders/폴더ID`라면 `folders/` 뒤가 폴더 ID입니다. 전체 폴더 주소를 넣어도 됩니다.
3. INI.gs 위쪽의 다음 줄을 찾습니다.

```javascript
JANDI_IMAGE_FOLDER_ID: '',
```

4. 작은따옴표 안에 새 ID 또는 폴더 주소를 넣습니다. 예시는 형식 설명용입니다.

```javascript
JANDI_IMAGE_FOLDER_ID: '여기에_새_폴더_ID',
```

5. 다른 항목의 `''`는 그대로 두세요. **빈 값은 기존 설정 유지**이며 삭제가 아닙니다.
6. 저장합니다. 화면의 함수 목록에서 **previewIniSettings**를 골라 실행합니다.
7. 실행 로그의 변경 목록이 `JANDI_IMAGE_FOLDER_ID`인지 확인합니다. ID나 비밀 주소는 로그에 출력하지 않습니다.
8. 함수 목록에서 **applyIniSettings**를 골라 실행합니다. 기존 JANDI 관리자 Google 계정으로 실행하세요. Google 권한 동의가 나오면 해당 프로젝트와 계정을 확인하고 진행합니다.
9. `설정 적용 완료: JANDI_IMAGE_FOLDER_ID`가 나오면 연결 설정이 저장된 것입니다. 폴더 접근 가능 여부와 휴지통 여부를 확인하고 저장하며, 실제 쓰기·새 JPG 링크 공유는 이후 이미지 전송 때 확인합니다.

초기 이미지 기능을 아직 켜지 않았다면 기존 **enableJandiCalendarImages**를 한 번 실행하세요. 이미 사용 중이었다면 다시 켤 필요가 없습니다. JANDI_ENABLED나 시험/토픽 모드는 자동으로 변경하지 않습니다.

## 6. 기존 웹앱 배포 갱신

1. 모든 스크립트 파일 저장.
2. 오른쪽 위 **배포 → 배포 관리**.
3. 현재 사용하는 웹앱 배포의 **수정(연필)** 선택.
4. 버전을 **새 버전**으로 선택하고 배포.
5. 기존 웹앱 탭을 닫고 같은 `/exec` 주소로 다시 접속.

새 배포를 별도로 만드는 것보다 기존 배포를 갱신하면 기존 주소를 유지할 수 있습니다. 코드 보관과 실제 배포는 별개입니다.

## 7. 실제 확인

`당직변경화면`에서 필요한 변경을 저장한 뒤 **잔디로 이미지 전송**을 직접 눌러 확인하세요. 이 설치 작업 자체는 메시지를 보내지 않습니다. 기존에 성공한 동일 변경은 중복 방지 때문에 다시 전송하지 않으며, 확인을 위해 허위 변경을 만들 필요는 없습니다. 다음 실제 변경 때 확인하면 됩니다.

새롭게 생성되는 JPG부터 새 폴더에 저장됩니다. 기존 이미지·폴더·권한·이력은 보존하고 이동하지 않습니다. 실패한 기존 전송을 재시도하면서 이미 만든 파일을 재사용하는 경우에는 이전 폴더의 파일이 유지될 수 있습니다. 폴더 자체를 공개 공유하지 않으며 이전과 동일하게 새 JPG만 링크 조회 공유를 요청합니다.

## 8. 다음에 바꿀 때

INI 상단의 필요한 한 줄 변경 → 저장 → previewIniSettings → applyIniSettings 순서입니다. ID 변경만이라면 **같은 프로젝트의 스크립트 속성에 즉시 반영**되므로 이미 v4.4.16을 배포한 뒤에는 ID 변경만으로 매번 배포할 필요는 없습니다. 함수나 화면 코드를 바꿨다면 새 버전 배포가 필요합니다.

인증키·웹훅 비밀값은 기존 **프로젝트 설정 → 스크립트 속성**에서 관리합니다. INI.CS나 소스에 비밀값을 기재하지 않습니다. 설정 코드 파일과 업무 JSON 백업에는 이 값이 포함되지 않으므로 별도 보관이 필요합니다.

설정 적용 직전 값은 스크립트 속성 **INI_PREVIOUS_SETTINGS**에 최근 한 번 기록합니다. 이는 자동 복구 버튼이 아니며 운영 데이터 백업도 아닙니다. 폴더를 잘못 지정했으면 이전 폴더 ID를 INI 상단에 넣고 다시 미리보기·적용하세요.

원본 시트는 저장 확정 정보와 함께 연결되어 있어 단순 ID 교체를 막습니다. 기존 캘린더도 이벤트 연결이 있으면 교체를 막습니다. 이 둘은 데이터·이벤트 연결 이관을 함께 해야 하므로 설정 파일에서 값만 바꿔 무리하게 넘기지 않습니다. 기존 캘린더의 ID를 지우는 방법으로 우회하지 마세요.

메일·NAS 기능은 추가하지 않았습니다. 원본 데이터·직원 배치·사진·변경/복구 이력·수동 잔디 전송을 유지합니다.
