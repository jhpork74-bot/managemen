# v4.4.17 스프레드시트에서 연결 ID 관리

기존 운영 스프레드시트에 **연결설정** 탭을 추가합니다. 이후에는 파일의 ID를 고치는 대신 시트의 노란 **C열**에 입력하고 적용합니다. 기존 업무·당직·사진·이력·잔디 설정은 유지합니다.

로컬·모의 Google Sheets/서버·Edge 회귀 검증 완료이며 실제 운영 시트 생성·배포·Drive 쓰기·잔디 수신은 미실행입니다.

## 1. 화면 구성

| A열 | B열 | C열 · 노란색 | D열 | E열 | F열 |
|---|---|---|---|---|---|
| 항목 이름 | 설정 키 | 변경할 값 | 현재 적용값 | 설명 | 상태 |

관리 항목은 원본 업무 스프레드시트, 잔디 달력 JPG 폴더, 업무 사전알림 캘린더, 당직표 작성 알림 캘린더, 웹앱 /exec 주소, 관리자 Google 계정입니다. 첫 생성 시 기존 설정을 자동으로 채웁니다.

**C열만 수정하세요.** B열은 설정을 구분하는 이름이고 D열은 마지막으로 불러온 적용값입니다. 빈 C열은 기존 값 유지이며 삭제가 아닙니다. 수식·중복 키·누락 행·알 수 없는 키는 적용을 중단합니다.

API 인증키와 잔디 Incoming Webhook 비밀 주소는 기존 프로젝트의 스크립트 속성에 남깁니다. 공동 편집하는 업무 시트에는 비밀값을 복사하지 않습니다. 직원/업무/사진/이벤트별 ID와 저장 잠금·영수증도 이동하지 않습니다.

시트를 찾을 최초 연결 ID 하나는 스크립트에 있어야 하므로 기존 INI.gs는 내부 연결 모듈로 유지합니다. 이후 일반적인 폴더 ID나 주소 변경은 시트에서 하며 INI.CS를 수정할 필요가 없습니다. INI.gs와 시트 양쪽에 서로 다른 값을 적어 번갈아 적용하지 마세요.

## 2. 설치 전

1. 웹앱 전체 백업을 내려받고 기존 Apps Script 소스를 PC에 보관하세요.
2. **현재 웹앱이 있는 같은 Apps Script 프로젝트**를 사용하세요. 새 프로젝트를 만들거나 다른 프로젝트에 분산 설치하지 마세요. ScriptProperties는 프로젝트마다 별개입니다.
3. 직원이 저장·자동작성·잔디 전송 중이 아닐 때 설치합니다.

## 3. v4.4.16을 이미 설치했다면

압축파일의 파일 두 개만 적용합니다.

1. `2_설정스크립트_추가또는교체/INI.gs`로 기존 INI.gs의 내용을 교체합니다. **교체 전 기존 INI_LEGACY_SPREADSHEET_ID를 메모하고 새 파일에서도 같은 값인지 확인하세요.** 기존 스크립트 속성은 삭제하지 않습니다. 이전 INI 상단에 적었지만 아직 적용하지 않은 값은 별도로 메모한 뒤 새 연결설정 시트의 C열에 입력하세요.
2. `1_새로추가할_스크립트/ConnectionSettings.gs`를 새 **스크립트** `ConnectionSettings`로 추가합니다.
3. 저장합니다. HTML은 교체하지 않습니다.

## 4. v4.4.16을 아직 설치하지 않았다면

v4.4.15를 쓰고 있다면 이번 묶음으로 바로 설치할 수 있습니다.

1. 현재 Code.gs의 `SPREADSHEET_ID` 작은따옴표 안의 ID를 메모하세요.
2. 스크립트 `INI`를 새로 만들고 `2_설정스크립트_추가또는교체/INI.gs` 전체를 넣으세요. `INI_LEGACY_SPREADSHEET_ID`를 방금 메모한 운영 ID와 같게 맞추세요. `INI_SETTINGS`의 빈 항목은 유지하세요.
3. 스크립트 `ConnectionSettings`를 새로 만들고 `1_새로추가할_스크립트/ConnectionSettings.gs`를 넣으세요.
4. `3_v4.4.16미설치시_추가교체_GS6개` 안의 Code.gs, FacilityStorage.gs, CalendarReminders.gs, DutyManagement.gs, JandiNotifications.gs, JandiCalendarImages.gs를 기존 같은 이름 파일에 각각 교체하세요.
5. 저장합니다. 나머지 모듈과 HTML은 유지합니다.

HTML을 .gs에 넣지 마세요. 이번 교체 파일은 모두 JavaScript 스크립트이며 첫 줄이 HTML 태그인 파일을 넣는 작업이 아닙니다. 기존 onOpen 함수가 별도로 있다면 통째로 덮어쓰지 말고 메뉴 코드를 병합해야 합니다. 제공된 v4.4.16 원본에는 기존 onOpen이 없습니다.

## 5. 연결설정 시트 만들기 — 처음 한 번

1. Apps Script 상단 함수 선택 메뉴에서 **setupFacilityConnectionSettings**를 선택하세요.
2. **실행**을 누릅니다. 현재 JANDI_ADMIN_EMAIL에 지정된 관리자 Google 계정으로 실행하세요.
3. 필요한 Google 권한에 동의합니다.
4. 실행 완료 후 기존 운영 Google 스프레드시트를 여세요.
5. 하단의 **연결설정** 탭을 누르세요.

기존 같은 이름의 다른 시트가 있으면 덮어쓰지 않고 중단합니다. 기존 업무 시트는 지우지 않습니다. 이 함수는 연결설정 탭과 안내를 만들 뿐 폴더를 바꾸거나 잔디 메시지를 보내지 않습니다.

## 6. 사진 폴더 ID 바꾸기

1. 연결설정 시트에서 **잔디 달력 JPG 저장 폴더** 행을 찾습니다.
2. 그 행의 **노란 C열**에 새 Drive 폴더 ID 또는 전체 폴더 주소를 넣습니다.
3. Apps Script 함수 **previewFacilityConnectionSettings**를 실행합니다.
4. 시트 F열에 해당 항목이 **미리보기: 변경 예정**으로 표시되는지 확인합니다.
5. Apps Script 함수 **applyFacilityConnectionSettings**를 실행합니다.
6. D열에 새 폴더 ID, F열에 **적용 완료**와 시간이 표시되는지 확인합니다.

쓰기·링크 공유 권한은 실제 새 JPG 전송 때 확인합니다. 새롭게 생성되는 잔디 달력 JPG부터 새 폴더에 들어갑니다. 기존 사진을 이동하거나 삭제하지 않습니다. 실패한 기존 전송을 재시도하며 이미 만든 파일을 재사용하면 이전 폴더의 이미지가 유지될 수 있습니다.

고장·공사 사진은 현재 업무 JSON 안에 압축 이미지로 저장됩니다. 이 Drive 폴더 항목은 잔디 당직 달력 JPG 전용입니다.

## 7. 시트 상단 메뉴를 사용하는 경우

웹앱 프로젝트가 해당 스프레드시트에 연결된 **바운드 스크립트**라면 시트를 다시 열었을 때 **시설관리 설정** 메뉴가 보입니다.

- **연결설정 시트 만들기·현재값 새로고침**: D열의 현재값을 다시 읽고 C열 입력은 보존합니다.
- **변경 미리보기**: 바뀔 항목을 F열에 표시합니다.
- **설정 적용**: 검사를 거쳐 실제 연결 설정에 저장합니다.

프로젝트가 **독립형**이면 메뉴가 표시되지 않습니다. 정상적인 Google 제약입니다. 이 경우 5~6단계처럼 Apps Script의 함수 선택 메뉴에서 실행하세요. 메뉴를 만들겠다고 다른 프로젝트에 프로그램을 복사하지 마세요.

Google 공식 문서: [맞춤 메뉴는 바운드 스크립트에서 지원](https://developers.google.com/apps-script/guides/menus).

## 8. 배포와 이후 변경

처음 이 코드를 설치한 뒤에는 기존 배포를 **배포 → 배포 관리 → 수정 → 새 버전**으로 갱신하세요. 기존 주소를 유지하고 웹앱 탭을 닫았다가 다시 접속합니다. 설정 시트 생성 함수는 편집기 최신 소스로 실행되므로 배포 전에 시트를 만들 수도 있습니다.

이후 ID만 바꿀 때는 **C열 수정 → 미리보기 → 적용**으로 끝납니다. 적용한 값은 기존 ScriptProperties에 저장되어 현재 프로그램이 읽습니다. 셀만 수정하고 적용하지 않으면 운영 연결은 바뀌지 않습니다. 코드 수정이 없으면 ID 변경만으로 재배포할 필요는 없습니다.

원본 시트와 기존 캘린더는 데이터/이벤트 연결이 함께 있어 단순 교체를 막습니다. 별도 이관이 필요하며 ID 삭제로 우회하지 않습니다. 다른 곳에서 설정이 바뀌었다는 오류가 나오면 **setupFacilityConnectionSettings**로 D열을 새로고침한 뒤 C열과 비교해 다시 미리보기 하세요.

최근 적용 전 값은 기존 **INI_PREVIOUS_SETTINGS** 속성에 한 번 보관합니다. 자동 복원 버튼이 아닙니다. 잘못된 폴더를 지정했다면 이전 ID를 C열에 넣고 다시 적용합니다.

업무 JSON 백업은 설정 시트와 ScriptProperties를 포함하지 않으므로 설정은 별도로 보관해야 합니다. 메일·NAS·자동 잔디 전송은 추가하지 않았습니다.
