# v4.4.23 변경 및 판단 근거

사용자는 v4.4.15에서는 저장 문제가 없었고 v4.4.22에서는 업무 완료 체크 등 여러 화면에서 충돌이 자주 났다고 보고했습니다. v4.4.15와 v4.4.22의 공통 저장 대기열은 동일했습니다. 서버 저장의 주요 차이는 연결설정 공통 모듈을 통한 시트·속성 접근입니다. 따라서 ‘v4.4.22가 버전 검사 방식을 바꾸어 발생했다’고 단정하지 않습니다. 배포본·트리거·다른 창의 실제 저장 요청 로그가 없어 특정 저장 주체까지 확정하지 못했습니다.

이번 개선은 재현된 공통 취약점을 수정합니다. 임시본의 원래 기준 데이터·버전을 보존하고, 충돌 시 세 자료를 비교하며, 다른 업무 영역과 독립적인 완료 변경을 합칩니다. 같은 업무 영역은 명시적으로 선택하고, 최근 저장 요청 결과를 확정 정보에 함께 보관합니다. 최신 변경 조회와 중복 불러오기 방지를 추가했습니다. 사진 입력창의 외부 임시 필드 아래로 같은 업무 영역을 자동 교체하지 않습니다.

실행 교체 파일은 Index.html과 FacilityStorage.gs 두 개입니다. 개발용 원본은 sync-merge.js / sync-recovery.js이며 build-sync.cjs가 v4.4.22 Index/base-index를 기준으로 두 파일에 반영합니다. 일반 기능 재빌드 후에는 build-sync.cjs의 기준 원본 전략을 검토하여 새 기능을 덮어쓰지 않도록 해야 합니다.

운영 서버 데이터·Drive 사진·잔디 메시지는 이번 작업에서 쓰거나 삭제하지 않았습니다. 이번 개선본은 다운로드용 로컬 보관입니다. 운영 검증을 완료한 안정판으로 표시하지 않습니다.
