# v4.4.20 잔디 달력 이미지 확인 후 다시 전송

사용자는 개인 시험 문자 수신을 확인했습니다. 첨부 화면의 20:07 메시지는 도착했지만 달력 이미지 대신 Drive 주소가 표시되어 있습니다. 같은 변경의 서버 성공 기록이 있으면 기존 버튼이 새 전송을 하지 않는 상태를 보완합니다. **실제 잔디 이미지 미리보기 표시는 아직 확인하지 않았습니다.**

기존 성공 기록을 지우지 않고 사용자가 확인 후 같은 최신 달력을 다시 보낼 수 있습니다. 업무 변경 이력을 가짜로 추가하거나 과거 영수증을 삭제하지 않습니다. 자동 재발송은 하지 않습니다.

## 1. 파일 교체 — v4.4.19 기준

현재 운영 프로젝트에서 기존 소스·업무 백업·스크립트 속성을 보관한 뒤 적용합니다.

| 종류 | 파일 | 작업 |
|---|---|---|
| 스크립트 GS | JandiNotifications.gs | 기존 같은 이름 파일 전체 내용 교체 |
| 스크립트 GS | JandiCalendarImages.gs | 기존 같은 이름 파일 전체 내용 교체 |
| HTML | JandiNotificationsUI.html | 기존 HTML JandiNotificationsUI 전체 내용 교체 |

새 파일 추가는 없습니다. HTML을 .gs에 넣지 마세요. **INI.gs, Code.gs, Index.html, DutyChangesUI 등 나머지 파일은 유지합니다.** 개인·회사 관리자 목록, 회사 사진 폴더, 잔디 Webhook 주소, 사진 서명키, 업무 데이터는 지우거나 바꾸지 않습니다. 전체복구용 폴더는 참고용이며 일괄 교체 대상이 아닙니다.

## 2. 배포 갱신

모든 파일 저장 → **배포 → 배포 관리 → 현재 웹앱 수정 → 새 버전 → 배포**. 기존 웹앱 탭을 닫고 같은 /exec 주소로 다시 접속합니다. 이전 탭은 새 버튼이 보이지 않을 수 있습니다.

## 3. 같은 달력 다시 전송

1. 당직변경화면에서 원하는 **장소와 월**을 선택합니다.
2. 제목 옆 **잔디로 이미지 전송**을 누릅니다.
3. 이미 서버 성공 기록이 있으면 아래 **잔디 이미지 전송** 영역에 **같은 달력 다시 전송** 버튼이 나타납니다.
4. 버튼을 누르면 대상 월·본관/분관·개인 시험 또는 직원 토픽을 확인하는 창이 뜹니다.
5. 실제 다시 보낼 때만 **확인**을 누릅니다. 취소하면 발송하지 않습니다.
6. 새 JPG를 회사 Drive 폴더에 만들고 잔디에 이미지 URL을 첨부한 메시지 한 건을 요청합니다.

기존 성공 기록과 별도의 재전송 요청을 사용합니다. 같은 요청의 중복 클릭·응답 유실 후 결과 확인은 다시 발송하지 않습니다. 성공 후 다시 전송 버튼을 또 누르고 확인하면 사용자의 별도 의사에 따른 추가 한 건이므로 실제 중복 메시지가 생길 수 있습니다.

## 4. 결과 확인·실패 시

응답을 확인하지 못했으면 새 재전송 버튼을 반복해서 누르지 말고 **전송 결과 확인·재시도**로 같은 요청의 기록을 확인합니다. 이전 재전송이 처리 중·수신 불명인 상태에서는 새 재전송 번호로 우회할 수 없습니다. 잔디 수신 여부 확인과 별도 조치가 필요합니다.

월·장소·전송 대상 또는 최신 업무 변경이 바뀌면 이전 재전송 요청을 다른 대상으로 보내지 않습니다. 제목 옆 일반 버튼에서 새 대상을 다시 확인합니다. 새 실제 변경은 원래 방식으로 저장한 뒤 일반 전송을 사용합니다. 시험을 위해 가짜 변경을 만들 필요는 없습니다.

서버 성공 응답은 **실제 수신방에서 이미지가 표시됐다는 보증이 아닙니다.** 현재 모드가 개인 시험이면 해당 Incoming Webhook이 실제 연결된 방을 확인하세요. Google 관리자 이메일 두 개를 등록하는 것과 잔디 수신방은 별개입니다.

HTTP 2xx라도 잔디 응답 본문에 알려진 요청 오류 코드나 명시적 실패가 있으면 성공으로 기록하지 않도록 보완했습니다. 모호한 응답은 수신 불명으로 분리합니다. 과거 성공 기록을 근거 없이 실패로 바꾸지는 않습니다.

## 5. 이미지 대신 주소가 보이는 경우

이번 변경은 과거 영수증에 막힌 새 전송 경로를 제공합니다. Google Drive 이미지 URL을 잔디가 실제로 미리보기할 수 있는지는 외부 서비스에서 확인해야 합니다. 새 전송 후에도 메시지 안에 URL만 보인다면 새 메시지 시각과 화면을 기준으로 이미지 표시 문제를 이어서 확인해야 합니다. 해결됐다고 단정하지 않습니다.

이미지 URL의 외부 접근 검사와 회사 Drive 정책 확인을 유지합니다. 확인을 위해 회사 폴더 전체나 기존 고장·공사 사진을 공개하지 않습니다. 잔디용 새 달력 JPG의 기존 링크 공유 방식만 유지합니다. 사진을 다른 서비스에 업로드하거나 사진 저장 위치를 개인 Drive로 바꾸지 않습니다.

기존 설정·사진·당직표·변경/복구 이력은 보존합니다. 메일·NAS·자동 외부 발송을 추가하지 않았습니다. 로컬/모의 서버/Edge 검증이며 실제 운영 배포와 잔디 달력 이미지 수신은 미확인입니다.

참고: [잔디 공식 Incoming Webhook 형식과 오류 코드](https://support.jandi.com/ko/articles/connect-incoming-webhook-21bc249f).
